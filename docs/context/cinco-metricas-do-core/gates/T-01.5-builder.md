## 2. O que mudou, em uma frase

`build_stream_handler` deixa de instalar `logging.Formatter` e passa a instalar
`ExtraRenderingFormatter` — que renderiza o `log_format` **inalterado** e, **somente quando o
registro carrega atributo posto pelo chamador via `extra={}`**, acrescenta ` chave=valor`
ordenado por chave.

`_STABLE_FORMAT` **não foi tocado**: continua `"%(message)s"`.

---

## 3. ⚠️ DESVIO DECLARADO DA LETRA DE `ADR-035/D3` — leia antes de aprovar

`ADR-035/D3` escreve: *"a troca é **no handler do processo de serviço** (escritor, coletor),
nunca no handler de projeção"*. **Um handler separado só ajuda se os processos de serviço forem
editados para instalá-lo** — e `single_writer_cli.py` / `collectors_cli.py` são exatamente os
dois arquivos que a restrição de paralelismo do Lote 1B proíbe esta task de tocar.

**Resolução adotada:** a distinção mudou de lugar — do **handler** para o **registro**.
É a mesma distinção vista do outro lado:

| | linha de projeção | evento de serviço |
|---|---|---|
| forma | `logger.info(canonical_json_line)` | `logger.info("event_name", extra={…})` |
| tem `extra`? | **não**, em nenhum dos 7 módulos de projeção | **sim** |
| o que o formatador faz | devolve **exatamente** o que `logging.Formatter` devolvia | acrescenta os pares |

**O custo que isso troca, nomeado em vez de escondido:** um handler separado manteria uma CLI de
projeção calada mesmo se ela ganhasse um `extra=` depois; este imprime e corromperia os bytes
hasheados. É um caminho de regressão real ⇒ ganhou guarda real (§5, teste 3).

**Não é ato de builder reescrever a ADR.** Se o `/architect` julgar que a letra de `D3` deve
passar a descrever o mecanismo por registro, é decisão dele — fica **nomeado aqui**, não
silenciado.

## 7. ⛔ Verde não prova nada até uma mutação reprovar — 4 mutantes, 4 mortos

Bancada com `PYTHONDONTWRITEBYTECODE=1`, `__pycache__` apagado, árvore restaurada e conferida
por `sha256` (`4a7497cdc7c806fa719bea83ab537f78e30b227380e573cab59bd0bcb801f1d8`) entre mutantes.
Comando de cada rodada: `make test-fast K="extra_rendering or ingest_health"`.

| # | mutante | o que ele simula | resultado |
|---|---|---|---|
| A | `if not extra:` → `if False:` | formatador contamina TODA linha, projeção incluída | **MORTO — 9 falhas**, entre elas `test_the_canonical_projection_still_hashes_to_the_reports_fingerprint` e 2 testes pré-existentes de `test_ingest_health_query.py` |
| B | `if not extra:` → `if True:` | volta ao comportamento antigo (contador invisível) | **MORTO — 5 falhas**, todas do lado de serviço |
| C | `sorted(extra)` → `extra` | ordem passa a seguir a inserção do dict | **MORTO — 2 falhas** |
| D | reservados `… \| {"message","asctime","taskName"}` → `… - {"exc_info","exc_text","stack_info"}` | campos internos do `LogRecord` vazam para a linha | **MORTO — 14 falhas** |

**O mutante A é o que importa:** ele é literalmente "o formatador passou a imprimir `extra` para
todo mundo", que é o defeito que a segunda metade do título existe para impedir. Ele **reprova**.

**E a guarda estrutural tem o próprio falsificador dentro da suíte:**
`test_the_projection_sweep_bites_a_planted_extra` planta uma CLI de projeção com
`logger.info("{}", extra={"n_rows": 1})` em `tmp_path` e exige que a varredura a **veja** — sem
ele, `test_no_projection_cli_emits_extra_on_its_product_logger` seria um sinal verde incapaz de
ficar vermelho, que é o modo de falha do `rc=0` que `ADR-012` nomeia.
