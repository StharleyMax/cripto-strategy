## 1. T-06.1 — helper que posiciona o eixo

### 1.1 Decisão: **gesto determinístico em malha fechada**, sem nenhuma superfície nova de produção

Três opções foram pesadas:

| opção | por que não / por que sim |
|---|---|
| **gancho de escrita na página** (`window.__setVisibleRange`) | ⛔ **recusada.** Os probes que existem (`window.__historyPageLatencyProbe`, `window.__axisLatencyProbe`) são **de leitura**. Um *setter* é a primeira escrita de estado do gráfico vinda de fora do gesto, instalada em produção, e o spec deixaria de exercer o caminho roda/arrasto → `onCandidateRange` → pager que é justamente o que eles provam. Por *build flag* (`NEXT_PUBLIC_E2E`) seria pior: o e2e passaria a testar um bundle que produção não serve (`e2e-env.sh` roda `next build` de produção hoje). |
| **query param** (`?e2eView=…`, como `e2eDenseSeries` em `host-series-feed.ts:32`) | ⛔ **recusada.** O precedente `e2e*` é **ablação** (o mesmo build medido nos dois braços, exigido por um falsificador), e muda O QUE é desenhado. | **gesto em malha fechada** (roda + arrasto, lendo os atributos que já existem) | ✅ **escolhida.** Zero mudança em `frontend/src`. Lê só o que a página já publica: `data-visible-logical-from/-to` e `data-bar-spacing-px` no host (`SymbolClient.tsx:648`), `data-window-start-ms`/`data-window-end-ms-inclusive` no `<main>` (`SymbolClient.tsx:4469-4470`), e o `requestedMs`/`drawnMs` do probe de paginação. |

**O que NÃO pode virar backdoor — e é critério de reprovação da task:** `git diff --stat
<base>..HEAD -- frontend/src` **vazio** para T-06.1. Se o builder concluir que precisa de um atributo

### 1.2 Assinatura

Módulo novo `frontend/e2e/view.ts` (não `helpers.ts`, que é de infraestrutura de app/API).
`stepMs` vem de `?interval=` via `SUPPORTED_TIMEFRAMES`/`DEFAULT_TIMEFRAME`
(`src/app/symbol/supported-timeframes.ts:68,78`) — e2e já importa de `../src` (**22** arquivos de `frontend/e2e/`, `grep -l 'from "../src' frontend/e2e/*.ts`, `[MEDIDO]`).

```ts
export interface ViewState {
  readonly fromLogical: number; readonly toLogical: number; // data-visible-logical-from/-to
  readonly barSpacingPx: number;                              // data-bar-spacing-px
  readonly windowStartMs: number; readonly windowEndMsInclusive: number; // <main>
  readonly stepMs: number;                                    // ?interval= → SUPPORTED_TIMEFRAMES
  readonly slotCount: number;                                 // (end − start) / step + 1
}
export type ViewTarget =
  | { readonly kind: "lastBars"; readonly bars: number }                        // N barras na borda direita
  | { readonly kind: "timeRange"; readonly fromMs: number; readonly toMs: number }; // instantes na tela
export interface ViewOptions {
  readonly toleranceSlots?: number;    // default: max(1, 2% do span alvo)
  readonly allowPaging?: boolean;      // default false ⇒ LANÇA se requestedMs cresceu
  readonly minBarSpacingPx?: number;   // zoom-in extra até o espaçamento (38 measurePhase, 15/30/35)
  readonly maxIterations?: number;     // default 12 — limite R9, e o trace sai no erro
}
export interface ViewReached extends ViewState {
  readonly iterations: number; readonly pagesRequested: number;
  readonly trace: readonly { action: string; from: number; to: number; spacing: number }[];
}
export function readView(page: Page): Promise<ViewState>;
export function showView(page: Page, target: ViewTarget, options?: ViewOptions): Promise<ViewReached>;
```

### 1.3 Como posiciona (o algoritmo que o builder implementa)

1. Converte o alvo em `[L, R]` lógico: `lastBars` ⇒ `R = slotCount`, `L = R − bars`; `timeRange` ⇒
   `(ms − windowStartMs) / stepMs`.
2. **Zoom**: cursor no pixel da âncora (`R` para `lastBars`; centro do alvo para `timeRange`, depois de
   trazê-lo à tela), roda com sinal pela necessidade. A biblioteca amplia **em torno do cursor**
   (`[MEDIDO por T-05.1: cursor na última barra ⇒ to 5761,9 contra 5760 do master]`). Delta
   proporcional à razão de spans, **metade ao inverter o sentido** (bissecção), até o span estar na
   tolerância. Alvo maior que o piso ⇒ **lança** `"abaixo do piso: N slots pedidos, piso P"` — nunca
   para "perto".
3. **Pan**: `dx = (fromLogical − L) × barSpacingPx` (arrastar à direita revela o passado, convenção
   medida em `e2e/16`), em fatias de ≤ 45% da largura (teto do arrasto em `gates/T-05.1-build.md` §2),
   com as pausas de 100 ms que a biblioteca precisa para ver arrasto e não teleporte.
4. Depois de **cada** gesto: espera a mudança de `data-visible-logical-from` com `expect.poll` limitado
   (≤ 2 s), **não** `waitForTimeout` fixo — as cópias de hoje pagam 250–700 ms por passo.
5. **Paginação**: `requestedMs.length` antes/depois. Cresceu e `allowPaging` é falso ⇒ **lança** com o
   trace. Com `allowPaging`, espera `drawnMs.length === requestedMs.length` antes de medir de novo.
6. **Pós-condição dura**: `|from − L| ≤ tol` e `|to − R| ≤ tol`, senão lança com o trace. Termina com o
   mouse em `(2, 2)` (crosshair fora — a legenda lê o crosshair).
7. Alvo já na tela ⇒ **0 gestos** (é o CALA do helper).

`[NÃO SEI]` — (a) se `data-window-start-ms` coincide sempre com `axis.startMs` depois de página
anteposta (`<main>` usa `panels.window.startMs`, o eixo usa `pager.axis`, `SymbolClient.tsx:4392`):
o spec do helper (§1.5 F3) tem de cruzar os dois uma vez, depois de paginar; (b) se a vela viva do
SSE desloca a vista durante o posicionamento (`shiftVisibleRangeOnNewBar`) nos specs com stub vivo;
(c) se há escala de preço à esquerda deslocando `x(lógico)` — o builder mede `x` por
`(lógico − from) × spacing` contra a legenda do crosshair uma vez.

### 2.4 O veredito — os dois modos não podem ser confundidos

1. **Palavra diferente**: completo `veredito: VERDE — 8 portões … · e2e COMPLETO 39/39 specs`; escopo
   `veredito: VERDE-ESCOPO — 7 portões completos + e2e em 4/39 specs (11 pixel · 22 diff · 37 mapa ·
   29 extra) — NÃO é o verde da wave`. `grep '^veredito: VERDE —'` não casa o de escopo.
2. **`e2e N/M specs` no completo**, com `N` contado no log (arquivos únicos nas linhas `›
   frontend/e2e/NN-` do reporter) e `M` = `ls frontend/e2e/*.spec.ts`. `N < M` no modo completo ⇒
   **não é VERDE** (rc=1): é a prova de que o completo rodou completo.
3. ⛔ **O escopo NUNCA grava o cache da árvore** (`verify.sh:350`). Sem isso, o `make verify` da wave
   sobre a mesma árvore limpa devolveria `VERDE (cache da árvore)` de uma rodada por escopo — o defeito
   mais caro deste desenho. O escopo **pode ler** o cache (verde completo implica verde de escopo).
   Escopo que resolveu COMPLETO roda e imprime como completo, e aí grava.
4. `rc` continua 0/1/3 nos dois modos: a distinção vive na palavra, no `N/M` e no cache, não no `rc`.
5. **Segundos por portão** no resumo (`$SECONDS` antes/depois de `portao`) — é o instrumento do DoD 2,
   e hoje ele não existe (M3 teve de sair de `mtime − início`).
