## O que muda premissa: leia antes de implementar

1. **`getHTMLElement()` do pane devolve `null` no mesmo tick de `addPane`/`addSeries`.** Ele só vem depois do primeiro
   frame. O overlay de título, legenda e badge (`DESIGN-LAYOUT` §6, plano 01 item 1.5) precisa ser ancorado
   **depois** do primeiro frame, não no mount.
2. **A `LineSeries` da 5.2.1 liga os pontos por cima da ausência.** No OI em 1m, 84,9% dos slots aparecem como
   valor interpolado. **Hoje, com 6 charts, o comportamento é o mesmo**, então não é regressão da F1, e a F1 mantém
   as formas atuais. Mas isso contradiz a política de ausência (RN-2/RN-4) e o `ARQ-1` §2 no caso de linha.
   **Dono: `/architect`.** Fica registrado como achado pré-existente e **não** deve ser corrigido de passagem
   numa task da F1. A F3b, que troca a linha de OI por candle, o resolve para o OI.
3. **`setCrosshairPosition` num slot vazio desenha a vertical nos 6 panes.** Isso é bom para o crosshair
   compartilhado.
4. **Opções de pane passadas dentro de `createChart` reprovam no teste `DR-1`.** Aplique-as depois, com
   `applyOptions`, como o spike faz.
5. **A API real não manda cabeçalho CORS.** Paginação feita no browser sem o proxy só-leitura fica bloqueada.
6. **F-2 contra a API real:** ~3,3 s por página, e ~99% desse tempo é a API. Hoje é o mesmo (3,46 s). É achado de
   **backend**, fora do escopo da F1.
7. **O hook de escrita recusa `frontend/src/app/spike/`**, que fica fora do escopo declarado. Código de apoio vai sob
   `frontend/src/app/symbol/`.
8. **`make verify` numa worktree nova dá INDETERMINADO** se faltarem `backend/.venv` e `data/`. Crie os dois antes
   de acreditar no portão.
