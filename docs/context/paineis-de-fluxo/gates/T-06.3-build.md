## O que mudou

| | antes | depois |
|---|---|---|
| `read_bounds`, `MIN` | `MIN(bucket_end)` — o planner o reescreve como `LIMIT 1` sobre `bucket_end` com a série como filtro | `MIN` dos primeiros `bucket_end` por `source` (`DISTINCT ON (source) … ORDER BY source, bucket_end`) — SkipScan na PK existente, **0 índice novo** |
| `read_bounds`, `MAX` | `MAX(bucket_end)` | o mesmo (subconsulta escalar). `DISTINCT ON … DESC` não pega SkipScan (desenho §1.2) |
| `__main__` | `uvicorn.run(app, host, port)` | `API_WORKERS` ausente ou `1` ⇒ **a mesma chamada**; `> 1` ⇒ `uvicorn.run("src.main:app", workers=n, limit_max_requests=API_LIMIT_MAX_REQUESTS, limit_max_requests_jitter=limite//10)`; `< 1` ⇒ `InvalidWorkerCountError` |
| `compose.yml`, `api` | — | `API_WORKERS: "2"`, `API_LIMIT_MAX_REQUESTS: "2000"`, `mem_limit: 1536m`, comentário datado; `command:` e imagem iguais (`ADR-027/D1`) |

`init: true` (recomendado, não obrigatório no desenho §2) **não** entrou: fora do escopo literal da task.
