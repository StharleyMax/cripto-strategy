## O que foi conferido e se sustenta

- **`ADR-045/D1` (`oi_candle.py:325-360`):** a âncora é uma busca exata por `T0` num `dict`. Sem `p(T0)` e com `|S|≥2`, o `open` é a primeira leitura de `S`. Sem `p(T0)` e com `|S|≤1`, não há candle. `high/low` vêm de `{open} ∪ S`. As leituras são validadas (na grade, estritamente crescentes, finitas) antes da projeção. Não achei caminho que costure a âncora ao último ponto antes de um buraco.
- **`D2-bis` (`oi_candle_regimes.py:164-232`):** cada chamada a `project_oi_candles` vê uma série só. O polling só fica com o bucket se `open_at_ms == T0`. O histórico é suprimido se houver qualquer âncora de polling dentro do span. Os slots são checados, não presumidos (`_require_slot`), e o instrumento também (`_require_same_instrument`).
- **Leituras (`series_history.py::oi_point_readings`):** só entra uma leitura em que `as_of(t)` devolve o fato de `bucket_end == t`. Isso corta o carry-forward do `STOCK`, que de outro modo inventaria um `p(T0)`.
- **Front:** o parser do envelope (`series-history-envelope.ts`) cobra `low ≤ min(o,c) ≤ max(o,c) ≤ high`, `open_at < close_at ≤ bucket_end` e `derived_from` declarado. Os dois primeiros valem por construção no backend, como está no ramo de `D1` acima. `hlUnmeasured` (`oi-regime-marks.ts`) conta `present + anchor ≤ 2`, e isso equivale a "o conjunto `{open} ∪ S` tem no máximo 2 amostras". O candle é posto na grade em `bucket_end_ms`, a mesma chave dos `rows` reagregados.
