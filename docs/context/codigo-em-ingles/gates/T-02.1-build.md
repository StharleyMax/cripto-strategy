## 6. ERRATA 1 — `ligados_distintos` é **54**, não os **55** que o DoD exige

**A contagem certa é a minha; o número do DoD está errado, e a causa é o próprio mapa normativo.**

```
$ python -c "<ast: Name(Store) U arg U FunctionDef U AsyncFunctionDef U ClassDef>"
file1  ANTES 15 -> DEPOIS 15   (DoD exige 15)  OK
file2  ANTES 55 -> DEPOIS 54   (DoD exige 55)  DIVERGE
```

**Por que 54 é o valor correto, e não sinal de código apagado.** Aplicando o mapa fechado ao conjunto
ANTIGO de nomes, o conjunto previsto tem **54** elementos, e ele bate **exatamente** com o medido:

```
DEPOIS - previsto (nomes a mais)   : []
previsto - DEPOIS (nomes perdidos) : []
```

**A colisão, nomeada:** o mapa manda `processo`→`process`, e **`process` já existia** no conjunto antigo
— é o método `ContadorDeTrabalho.process` (hoje `WorkCounter.process`). Dois nomes distintos antes, **um
só** depois: `55 - 1 = 54`. O mapa **não é injetivo** sobre o conjunto de nomes deste arquivo.

**O `55` do DoD pressupõe bijeção**, e essa premissa é falsa contra o mapa que o próprio `SPEC-002` §3.1
fixa. A metade `ligados_distintos` do `CA-F2-2` existe para pegar **código apagado** (*"só a primeira
seria satisfeita apagando código"*) — e o que ela pegou aqui não é apagamento: nada se perdeu
(`previsto - DEPOIS = []`), e a linha de base comportamental (`107`/`370`/`54`) está intacta.

⇒ **Leitura correta do critério:** `file1` = **15** e `file2` = **54**. Registro a errata em vez de
forçar o código a bater com o número — forçar significaria desfazer `processo`→`process`, que é
**mandado pelo mapa normativo**, ou inventar um 55º nome.

## C2.7 — Conflito entre dois critérios da própria SPEC: `CA-F2-7` × `ADR-013/D3`

removidas**. Essa forma distingue *append* de *reescrita*, que é precisamente o que "append-only"
quer dizer; `vazio` colapsa as duas e proíbe as duas.

por quem tem competência para decidir; uma linha indevida em documento append-only **não se remove**.
