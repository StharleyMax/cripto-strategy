## 1. O que a prova estabelece

`collectors_cli` (o coletor) e `create_app` (a API, `src.main`) são **dois composition roots
diferentes**, cada um abrindo sua **própria** conexão `psycopg`, apontados para o **mesmo**
container `timescale/timescaledb:2.17.2-pg15` efêmero. Depois de **1 sessão** `!forceOrder@arr`
(fechada por `SIGTERM`, como `test_collectors_cli_shutdown.py` já prova para `sqlite`) e **1
ciclo** `premiumIndex` (que dispara uma vez no boot, com `PREMIUM_INDEX_CYCLE_INTERVAL_S` grande
o bastante para não disparar de novo antes do `SIGTERM`), `GET /api/v1/collector-status` responde
`n_rows >= 2` — um `(source, endpoint)` por produtor, nunca 0 nem 1, que é o que aconteceria se a
API estivesse lendo um motor diferente do que o coletor escreveu (`ADR-031/F2`).

## 2. Comando executado e resultado — ponta a ponta, manual, fora do pytest

Rodado uma vez, à mão, precisamente para que o número abaixo tivesse o comando literal do DoD
(`curl … | jq .n_rows`) e não só a asserção do teste automatizado (§3).

```bash
# 1. container efêmero
docker run -d --rm --name t-02-8-manual-proof \
  -e POSTGRES_PASSWORD=do-not-leak-me-manual -e POSTGRES_USER=manual_user \
  -e POSTGRES_DB=manual_db -p 127.0.0.1::5432 timescale/timescaledb:2.17.2-pg15
docker port t-02-8-manual-proof 5432/tcp   # -> 127.0.0.1:34596

# 2. coletor real (collectors_cli.run(), Redis fake, HTTP fake — store REAL em postgres)
cd backend
INGEST_RECORD_BACKEND=postgres POSTGRES_HOST=127.0.0.1 POSTGRES_PORT=34596 \
POSTGRES_DB=manual_db POSTGRES_USER=manual_user POSTGRES_PASSWORD=do-not-leak-me-manual \
PYTHONPATH=. .venv/bin/python tests/helpers/collectors_cli_postgres_driver.py &
# ... aguarda o ciclo premiumIndex aparecer em md.ingest_run, então:
kill -TERM <pid>   # fecha a sessao !forceOrder@arr, rc=0

# 3. API real sobre o MESMO container (create_app via src.main:app, composição por env)
INGEST_RECORD_BACKEND=postgres POSTGRES_HOST=127.0.0.1 POSTGRES_PORT=34596 \
POSTGRES_DB=manual_db POSTGRES_USER=manual_user POSTGRES_PASSWORD=do-not-leak-me-manual \
QUARANTINE_STORE_PATH=<scratch>/series_quarantine.sqlite3 \
.venv/bin/python -m uvicorn src.main:app --host 127.0.0.1 --port 18123 --log-level warning &

# 4. O COMANDO LITERAL do DoD:
curl -s http://127.0.0.1:18123/api/v1/collector-status | jq .n_rows
```

**Resultado `[MEDIDO 2026-09-08]`:**

```
2
```

Universo: 1 container Postgres, 1 sessão `!forceOrder@arr` (`verdict=ACCEPTED`, `n_published=0`
— fake sem mensagens), 1 ciclo `premiumIndex` (`verdict=ACCEPTED`, `n_published=0` — fake com lote
vazio), 2 linhas em `md.ingest_run` antes da leitura (confirmado por
`select source, endpoint, count(*) from md.ingest_run group by 1,2` → 2 pares, ambos
`binance-futures`, endpoints `!forceOrder@arr` e `/fapi/v1/premiumIndex`). O envelope completo
(`n_rows=2`, 2 objetos em `rows`, um por endpoint) foi conferido, não só o campo `n_rows`.

**Morde — a mesma pergunta, API apontada para `sqlite` vazio (nenhum coletor jamais escreveu
nela):**

```bash
INGEST_HEALTH_STORE_PATH=<scratch>/empty_ingest_health.sqlite3 \
QUARANTINE_STORE_PATH=<scratch>/series_quarantine.sqlite3 \
.venv/bin/python -m uvicorn src.main:app --host 127.0.0.1 --port 18124 --log-level warning &
curl -s http://127.0.0.1:18124/api/v1/collector-status | jq .n_rows
```

**Resultado `[MEDIDO 2026-09-08]`:** `0` — exatamente a alternativa que o DoD nomeia ("API em
sqlite ⇒ 0 ou 1"). O falsificador morde: trocar o motor sem trocar o dado muda o número que o
gate mede.

## 3. A mesma prova, repetível — `pytest`

`backend/tests/sentimento/test_collector_status_dual_process_postgres.py` automatiza os dois
lados do §2 (positivo e morde), para que a evidência não dependa de um operador repetir o roteiro
manual:

- `test_collector_status_reports_at_least_two_rows_over_a_real_shared_postgres` (pulado sem
  `docker`): sobe o MESMO container efêmero (`timescale/timescaledb:2.17.2-pg15`), roda
  `collectors_cli.run()` real num subprocesso (`tests/helpers/collectors_cli_postgres_driver.py`
  — Redis fake, `SIGTERM` fecha a sessão, mesma técnica de `test_collectors_cli_shutdown.py`),
  compõe a API via `create_app()` (sem `store_path`, logo pela mesma
  `compose_ingest_record_store` que o coletor usa) e afirma `n_rows >= 2` e que os dois
  `endpoint`s aparecem nas `rows`.
- `test_collector_status_reports_zero_rows_over_an_unrelated_sqlite_store` (sem `docker`): a
  metade morde — `create_app(store_path=<tmp sqlite vazio>)` responde `n_rows == 0`.

```bash
cd backend && .venv/bin/pytest tests/sentimento/test_collector_status_dual_process_postgres.py -v
```

**Resultado `[MEDIDO 2026-09-08]`:** `2 passed` (universo: 2 testes, o positivo com Postgres real
via Docker e o morde sem rede alguma).
