**PRECISA REWORK**: `frontend/src/app/api/series-history/route.ts` viola `ADR-005/D5` ("Next não

alternativas recusadas daquele ADR lista, custo declarado *"reabre a porta de segunda verdade que

## O rework, na ordem

1. **Delete** `frontend/src/app/api/series-history/route.ts` e o teste/módulo que só existe para
   ele (`frontend/src/app/api/series-history/status-mapping.ts` + `.test.ts`, se não tiverem uso
   fora dessa rota).

2. **Siga o precedente que já existe no repo** para exatamente este problema
   (`INGEST_HEALTH_API_BASE_URL` nunca é `NEXT_PUBLIC_*`, `ADR-019/D4`):
   `frontend/src/app/symbol/[symbol]/page.tsx:390` (`buildLiveUrl`) + as chamadas em
   `~862-864` — o Server Component lê `process.env.INGEST_HEALTH_API_BASE_URL` **uma vez**, monta
   a URL absoluta, e passa **já resolvida** como prop (`liveUrls`) para `SymbolClient.tsx`, que
   abre `new EventSource(url)` (`~2493`) — conexão DIRETA browser→FastAPI, Next nunca intermedia
   o corpo. Faça o mesmo para a paginação de histórico: `page.tsx` resolve e passa a base URL (ou
   um builder equivalente a `buildLiveUrl`) como prop nova; `browser-series-history-client.ts`
   passa a montar a URL ABSOLUTA a partir dessa prop e fazer `fetch` direto contra o FastAPI —
   nunca mais um caminho relativo `/api/series-history`.

   ⚠️ **Não troque isso por um fetch de caminho relativo tipo `/api/v1/series-history`
   confiando no reverse-proxy do Caddy** (`deploy/Caddyfile`, mesmo origin em produção via
   `handle {$API_PREFIX}/* { reverse_proxy api:... }`). Isso quebraria o `npm run dev`/e2e local,
   que não passa pelo Caddy — Next dev server não tem rota registrada para `/api/v1/*` e devolveria
   404. A URL tem que continuar vindo de `INGEST_HEALTH_API_BASE_URL` resolvida no servidor, igual
   ao `EventSource`, não de um caminho relativo hardcoded.

3. **CORS**: `[MEDIDO]` — não há `CORSMiddleware`/`allow_origins` em `backend/src` (grep confirma
   0 ocorrências) e mesmo assim o `EventSource` já funciona cross-origin hoje, então o ambiente de
   dev/e2e já tolera isso de algum jeito (confirme rodando o teste que exercita o `EventSource`
   antes de assumir que o fetch novo vai falhar por CORS; se falhar, é achado novo, registre no QA
   Gate Context Block em vez de adicionar `CORSMiddleware` por conta própria — isso seria decisão
   de arquitetura nova).

4. `fetchSeriesHistoryViaHttp`/`series-history-envelope.ts` — confirme que nada ali tem
   dependência Node-only antes de chamá-los diretamente do lado do browser (o arquiteto apontou
   isso como pendência, não verificou).

5. Depois do rework, rode a suíte completa de novo (`npm --prefix frontend run lint/typecheck/test:app`)
   — o handoff original (`docs/context/candle-real-e-eixo-unico/handoff/T-05.2.md`) continua
   valendo para o resto do escopo (D-C3.5, teto de 5.000 slots, paginação serial); só o transporte
   muda.
