## O que esta dispatch entrega

- **Serial, uma requisição em voo por grade** — nunca paralelo, nunca uma nova disparada antes da
  anterior responder (a lib não tem `prepend`; `setData` é do array inteiro, custo linear no total
  acumulado ⇒ quadrático em páginas se não travar a concorrência).
- **Teto de ~5.000 slots por grade**, descartando a ponta direita — nunca crescimento ilimitado.
  Números medidos que justificam o teto: `setData` de 5.760×6 = 48,2ms; 21.600×6 = 125,1ms;
  129.600×6 = 752,6ms (`D-C3.5`, `probe3.mjs`, jsdom — teto superior, browser real é mais rápido,
  mas a ordem de grandeza vale). Com ~500 velas/página e teto ~10 páginas (5.000 slots), o
  remonte fica em ~50ms.

Não implemente T-05.5 (os três estados no contrato) nem T-05.9 (teto de latência 400ms via
Playwright) — outras dispatches. Esta task é só o mecanismo de busca/paginação; o estado
`not-loaded`/`absent`/`beyond-coverage` do slot ainda não pedido é escopo de T-05.5.
