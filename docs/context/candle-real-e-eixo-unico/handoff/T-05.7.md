## O gap exato, já apontado pelo próprio código de T-05.2

`frontend/src/app/symbol/use-history-pager.ts:256` hoje monta:
```ts
const coverage: HistoryCoverage = { earliestBucketMs: coverageFloorMsRef.current, sourceFloorMs: null };
```
`sourceFloorMs` está **hardcoded `null`**, e `earliestBucketMs` só vem de `coverageFloorMs` — um
estado que **congela reativamente no edge de uma página que falhou** (comentário do próprio
arquivo, linha ~20: *"what T-05.2 still owes, on its own, is 'never loop forever': freezing
coverageFloorMs at the axis edge the failed attempt was"*). Isso é heurística client-observed, não
o horizonte **declarado** pelo servidor.

`T-05.5` (já mergeada nesta branch) entregou o parse de `panel.coverage.{earliest_bucket_ms,
latest_bucket_ms, source_floor_ms}` (`series-history-envelope.ts`, tipo `PanelCoverage`) e
`classifySlotCoverage` (`slot-coverage.ts`) — leia esse módulo primeiro, ele já tem a lógica de
"o que a cobertura declarada diz sobre um slot".
