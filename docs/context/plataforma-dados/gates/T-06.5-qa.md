## Mutação real (planta → confirma falha → reverte → `git diff` limpo)

Todas rodadas com `.venv/bin/python -m pytest backend/tests/sentimento/test_open_interest_catalog.py -q --no-cov` (12 testes coletados). Após cada mutação, `git diff --stat`/`git status --short` confirmou reversão limpa.

1. **D6.7** — `coinalyze_open_interest_key(reduction: Reduction, ...)` → adicionado default
   `= Reduction.CLOSE`. Resultado: **1 teste falha**
   (`test_asking_for_the_coinalyze_open_interest_key_without_reduction_is_refused` →
   `Failed: DID NOT RAISE TypeError`), os outros 11 continuam verdes. Prova que o falsificador
   do "pedir sem `reduction` é erro, nunca default silencioso" está de fato coberto.
2. **Colapso das 4 linhas Coinalyze** — `reduction=reduction` → `reduction=Reduction.CLOSE`
   fixo dentro de `coinalyze_open_interest_key`. Resultado: **8 de 12 testes falham**
   (as 3 variantes parametrizadas de OPEN/HIGH/LOW, a distinção de 5 identidades — `1 == 4`
   —, a contagem de 5 linhas do catálogo — `DuplicateSeriesKeyError` disparado dentro de
   `build_series_catalog` —, o lookup por identidade, o teste de sexta-linha-duplicada e o de
   `instrument_id`). Prova que a lógica de "4 linhas genuinamente distintas por `reduction`"
   está coberta por múltiplos testes independentes, não por um único assert frágil.
3. **Binance deixa de ser `POINT`** — `reduction=Reduction.POINT` →
   `reduction=Reduction.CLOSE` em `binance_open_interest_key`. Resultado: **2 testes falham**
   (`test_binance_open_interest_key_is_always_point_at_bucket_end` e a asserção de conjunto de
   `reductions` no teste das 5 linhas do catálogo — sem colisão de `series_key_id`, porque
   `provider` difere, o que por si só mostra que a defesa contra colisão cross-source não
   depende só de `DuplicateSeriesKeyError`, mas da asserção direta de `reduction`).
4. **`label_shift` zerado** — `OPEN_INTEREST_LABEL_SHIFT_MS = _INTERVAL_MS` → `= 0`.
   Resultado: **1 teste falha** (`test_open_interest_label_shift_is_positive_interval_not_zero`
   → `assert 0 == 300000`), confirmando que o `+interval` de `SPEC-001` §2.1 (D6.8, direção do
   shift) tem falsificador próprio, não é só citação em docstring.

Após as 4 reversões: `git status --short` e `git diff --stat` vazios — nenhum resíduo.
