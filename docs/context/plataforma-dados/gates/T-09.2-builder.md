Rodei o script sem alteração (comportamento publicado) e depois com **duas mutações**
aplicadas a uma cópia temporária (fora do worktree, nunca commitada), para provar que os 5
casos negativos pegam regressão real, não decoram um resultado:

1. **Mutação 1** — removida a checagem explícita de ausência da chave `env`. Resultado: o
   script **crasha** com `KeyError: 'env'` não capturado (`exit 1`) — a ausência da guarda já
   quebra visivelmente, não passa em silêncio.
2. **Mutação 2** — guarda inteira substituída por `return linha.get("env")` (aceita qualquer
   linha, mesmo sem `env`, mesmo com valor fora do conjunto). Resultado:
   ```
   REPROVADO — 5/9 caso(s) com veredito errado:
     - FALSO POSITIVO: linha invalida ACEITA (sem campo env (o caso que D9.3 nomeia)) -> {...}
     - FALSO POSITIVO: linha invalida ACEITA (env = None) -> {...}
     - FALSO POSITIVO: linha invalida ACEITA (env = string vazia) -> {...}
     - FALSO POSITIVO: linha invalida ACEITA (env fora do conjunto fechado ...) -> {...}
     - FALSO POSITIVO: linha invalida ACEITA (chave com erro de digitacao ('envs', plural)) -> {...}
   exit=1
   ```
   Os **5 casos negativos** capturam a regressão — nenhum passa em silêncio sob a guarda
   desligada. Isto é a prova, não a alegação, de que `D9.3` está satisfeito.
