## Ataque 4 — tentativa de achar segredo que escapa à regex nova

Testado e **calou corretamente** (não é achado): variação de capitalização de chave (`(?i:...)`
cobre), aspas simples/duplas ao redor do valor, `Dockerfile` sem extensão — este último continua
**`[NÃO MEDIDO]`, declarado em aberto pelo próprio `harness.toml:437-442`** (não é defeito novo, é
lacuna já confessada).

**Três escapes REAIS, não documentados, com segredo literal ficando fora do bloqueio** — cada um
criado como arquivo efêmero em `deploy/`, rodado e apagado na hora, nunca entrou em `git status`:

**(A) decoy `${...}` colado depois de um segredo literal real** — contradiz o próprio propósito que
o comentário do regex declara (`harness.toml`: "separar senha no arquivo de senha lida do
ambiente"):
```
$ printf 'services:\n  postgres:\n    environment:\n      POSTGRES_PASSWORD: hunter2_prod_master${UNUSED}\n' > deploy/.qa_atk_a.yml
$ harness rules --mode file --path deploy/.qa_atk_a.yml; echo $?

0
```
`hunter2_prod_master` é literal (não vem de `${VAR}` nenhum — `${UNUSED}` é apêndice morto), e a
linha cala porque a allowlist `\$\{` é verificada em **qualquer posição da linha**, não no valor
capturado.

**(B) segredo real + comentário de fim de linha com palavra da allowlist** — contradiz o propósito
declarado da allowlist ("valor de amostra declarado como amostra": aqui o VALOR não é amostra, só o
comentário menciona uma palavra da lista):
```
$ printf 'services:\n  postgres:\n    environment:\n      POSTGRES_PASSWORD: hunter2_prod_master  # changeme depois\n' > deploy/.qa_atk_b.yml
$ harness rules --mode file --path deploy/.qa_atk_b.yml; echo $?

0
```

**(C) YAML flow-style** (`environment: {POSTGRES_PASSWORD: hunter2_prod_master}`) — a chave não
começa a linha, e o regex ancora em `^` (avaliação linha a linha); qualquer segredo dentro de um
mapeamento *flow* nunca é avaliado:
```
$ printf 'services:\n  postgres:\n    environment: {POSTGRES_PASSWORD: hunter2_prod_master}\n' > deploy/.qa_atk_c.yml
$ harness rules --mode file --path deploy/.qa_atk_c.yml; echo $?

0
```

Os três são segredo literal, sem indireção de ambiente real, e a regra devolve silêncio (`rc=0`)
para os três. (A) e (B) não são só "regex imperfeita" genérica — cada um derruba, com um caso
concreto, a garantia que o próprio comentário da regra em `harness.toml` alega ter.
