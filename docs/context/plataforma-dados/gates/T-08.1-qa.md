## Checagem 2 — os números batem com o que os scripts produzem

**`FAIL`, achado real, reproduzido.** Rodei o pipeline documentado em
`docs/spike/T-08.1-motor-armazenamento/README.md` "Passo a passo (reprodutível)" de ponta a
ponta (fetch real da Binance, TimescaleDB `2.17.2-pg15` em Docker, DuckDB 1.5.5, pyarrow
25.0.1, psycopg 3.3.5 — mesmas versões do README). Candidato 4 bate: `hypertable_size` =
909.312 B (idêntico ao citado), `verify_timescale.py` → `OVERALL: PASS`, scan 0,048s.

**Candidato 5 não bate — o critério de espaço citado como PASS (1,989×) não é o que o
script commitado produz:**

1. `docs/spike/T-08.1-motor-armazenamento/write_parquet.py:37` chama
   `pq.write_to_dataset(..., compression="zstd")` **sem `compression_level`**. Rodando
   literalmente este script sobre o dataset reconstruído: `du -sb built/parquet` =
   1.236.601 B → **2,048×** o zipado da fonte (603.698 B) — **reprova** o critério ≤2×,
   não passa com "margem de 0,5%" como a emenda de `ADR-002` afirma.
2. Só ao adicionar explicitamente `compression_level=19` (parâmetro ausente do script
   commitado) o tamanho cai para 1.200.618 B → 1,989× — **o número que a emenda cita como
   resultado**. Ou seja, o número reportado (1.200.986 B / 1,989× / PASS) foi produzido com
   um parâmetro que **não existe** no `write_parquet.py` versionado.
3. Segundo sintoma do mesmo problema: `write_parquet.py:16` grava em `OUT_DIR =
   "built/parquet"`, mas `verify_duckdb.py:13` tem `GLOB = "built/parquet_z19/**/*.parquet"`
   hardcoded, e o passo `du -sb built/parquet_z19` do próprio README também usa esse nome.
   Seguindo o README ao pé da letra, `verify_duckdb.py` **quebra**:
   `_duckdb.IOException: IO Error: No files found that match the pattern
   "built/parquet_z19/**/*.parquet"` — reproduzido neste ambiente.

Os testes de fixture (3 classes, bit-idêntico) e o tempo de backtest do candidato 5
**seguem corretos** independente do bug de compressão — reproduzi `verify_duckdb.py`
apontando para o diretório real e `OVERALL: PASS` se confirma, 0,011s. O que não bate é
especificamente o critério de **espaço**, que é um dos cinco do DoD D8.21.

**Efeito na decisão:** não muda o candidato escolhido — corrigido, o candidato 5 reprova
com folga maior (2,048×, não 1,989× com margem de 0,5%), tornando o caso do candidato 4
ainda mais forte, não mais fraco. Mas o **documento afirma um número que o código não
produz**, e isso é exatamente "passa mas contraria o que o próprio artefato mede" — a régua
deste papel.
