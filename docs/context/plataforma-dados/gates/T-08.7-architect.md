# T-08.7 — decisão de arquitetura (quant-architect), pré-implementação

Status: decisão estrutural fechada, para o `builder` executar. **Nenhum código foi escrito por este
agente** — decisão, não implementação, por escopo do despacho (`CST-75`).

Decisão completa: [`docs/adr/ADR-022-min-obs-por-observacao-n-obs-por-ponto-e-dispersao-do-z.md`](../../adr/ADR-022-min-obs-por-observacao-n-obs-por-ponto-e-dispersao-do-z.md).

## Veredito

**`min_obs` é propriedade da OBSERVAÇÃO, não do agregado.** O `MinObsNotMetError` que `T-08.6` já
implementou (`scan.py:40-49`) checa só `n_total = len(values) < min_obs` — isso nunca teria pegado o
caso concreto do despacho (`rolling(2016, min_periods=576)` nunca encheu a janela nos alts): um agregado
de 2000 pontos mistos (BTC de janela cheia + alts de janela quase vazia) passa tranquilo nesse teste.
Correção: `float` nu vira `Observation(instrument_id, value, n_obs)` — só no caminho `scan`
(`ThresholdSpec.min_obs`/`window`); `distribution`/`histogram.py` **não mudam** (não têm esses eixos,
confirmado por leitura de `histogram_recipe.py`, não suposição). Filtro por `n_obs < min_obs` roda
**por observação**, antes de `_fires`; o check agregado de `T-08.6` continua vivo, agora sobre o
remanescente. Ausência é união discriminada (`Fired|NotFired|Insufficient`, sem campo de valor no
`Insufficient` — mesmo idioma de `FiringRateResult.rate: None` de `ADR-020/D5`), nunca `None` solto.
Dispersão do `z` (`IQR` entre símbolos sobreviventes, `≥4` ou `null`+motivo) é campo IRMÃO de
`ScanResult`, nunca lido por `_fires`/`_robust_z` — telemetria, não decisão, por construção de
assinatura (não por promessa em prosa).

## O que estava em jogo

| pergunta | resposta | evidência citada |
|---|---|---|
| `min_obs` de `T-08.6` já resolve o caso concreto? | **não** | checa só o tamanho agregado; o defeito é por símbolo/por ponto (`PRD-001:389`) |
| `n_obs`/dispersão do `z` exigem identidade por símbolo? | **sim** | `D8.5` pede dispersão CROSS-SÍMBOLO, ≥4 — impossível sem `instrument_id` amarrado a cada valor |
| `distribution`/`histogram.py` também precisam de `min_obs`? | **não** | `HistogramRecipe` nunca teve `window`/`min_obs`; contagem de bin é exata, não estatística resolvida sobre população pequena |
| dispersão pode virar um segundo filtro automático? | **não** | overfitting de segunda ordem — telemetria fica em campo separado, nenhuma função de decisão a recebe como parâmetro |
| algo de `T-08.6` quebra? | **não** | mudança é aditiva: teste existente (`test_percentile_spec_below_min_obs_refuses`) continua válido, porta sem adaptador concreto ainda (custo de migração zero) |

## O que este ADR não decide

Regra de `firing_rate` walk-forward (`T-08.8`, `D8.2` — tipo já existe em `ADR-020/D5`); a query SQL do
adaptador `ObservationSource` (`ADR-020/D7`, "do builder"); rota HTTP (`infra`, `T-01.8` sem juiz).

## Falsificador

População com `Observation` de `n_obs` misto (`n_obs=2016` vs `n_obs=300`, `min_obs=576`) tem que
devolver `n_excluded_min_obs==1` e um `Insufficient(instrument_id="ALTUSDT", n_obs=300,
min_obs_required=576)` — nunca um `Fired`/`NotFired` para essa observação. Detalhe completo na ADR.
