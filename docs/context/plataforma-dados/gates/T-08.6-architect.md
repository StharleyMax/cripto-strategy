## Veredito

**Bordas de bin são derivadas por quantil sobre a distribuição observada do próprio `(field, nature)`
— nunca corte absoluto fixo.** `field := (metric, unit, denom)`, 3 dos 15 termos de `SeriesKey`
(`sentimento.domain.series_key`), reusado por import — não redeclarado. `nature` é reusado do mesmo
módulo, sem enum duplicado. Overflow (esquerda e direita) é bin de primeira classe: sempre computado,
sempre exposto com `(count, share, extreme)`, e `sum(bins)+overflow+massas_pontuais == n_total` é o
invariante que um teste de regressão tem de fixar.

## Contrato de dado (motor → renderização), resumo — forma completa na ADR §D2–D7

```
HistogramResult = { field, nature, pointMasses[], bins[], overflowLeft, overflowRight, nTotal, universe }
FiringRateResult = { mode: "in_sample", rate: null } | { mode: "walk_forward", rate: number, nWindows }
HistogramRecipe (o que vai no bundle) = { specVersion, quantiles[], interpolation, pointMassMinShare }
```

`FiringRateResult.rate` é `null` **por tipo** quando `mode="in_sample"` — impede por construção a
armadilha de `D8.2` (célula mostrando `1,04%` quando `eval==calib`); a regra de QUANDO usar cada modo é
`T-08.8`, não esta task.

## O que este ADR não decide, e por quê — não é omissão, é fronteira

- Rota HTTP/serialização (`infra`, `T-01.8` sem juiz).
- Honestidade de `firing_rate` (`T-08.8`) e `min_obs`/`n_obs`/dispersão de `z` (`T-08.7`) — o contrato
  reserva os campos, as tasks decidem os números.
- Query SQL contra TimescaleDB — a ADR fixa a PORTA (protocolo Python que `use_cases/` chama), a
  implementação concreta é do builder.

## Falsificador que o builder tem que fazer passar

Fixture do taker (mesmo dataset de `D8.6`), `recipe.quantiles=[1,99]`, `pointMassMinShare` fora do
alcance do taker → `overflowRight` reproduz **proporcional a 1%** (nunca os 47,2% da tabela fixa
antiga), com `extreme` batendo em **2055,3%**. Formato completo na ADR, seção "Falsificador desta ADR".
