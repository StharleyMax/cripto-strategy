## Achado — não-bloqueante, observação para `T-08.7` herdar

`resolvePointerAction` não ecoa `input` (click vs space) de volta no caso `annotate_reserved` (`PointerAction` só carrega `{kind:"annotate_reserved", mode:"annotate"}`). Hoje não perde informação de fato — o chamador já possui `input` como argumento próprio. Mas se `T-08.7` precisar que clique e Espaço produzam ações DIFERENTES dentro de `annotate` (ex.: clique marca ponto, Espaço abre edição), o tipo atual força reconstruir o discriminador fora deste módulo. **Não bloqueia esta task** (escopo declarado explicitamente exclui implementar marcação); estender `PointerAction` com `input` opcional depois é aditivo, não breaking.

## O que NÃO foi encontrado — checado e limpo

- **Ordem da pilha de camadas**: `LAYER_ORDER = ["plot","overlay","crosshair"]` confere com `SPEC-001:284`; `assertOverlayIsSandwiched` tem 3 casos MORDE distintos no teste (overlay abaixo de plot, acima de crosshair, conjunto incompleto).
- **Acessibilidade de teclado, na camada que este módulo controla**: `PointerInputKind = "click" | "space"` trata clique e Espaço como entradas simétricas de primeira classe, ambas exigidas pelo mesmo teste — estruturalmente impossível implementar `click` em `T-08.7` sem decidir `space`, o que é a arquitetura certa para WCAG 2.1.1 (operável por teclado).
- **Case sensitivity como parte do contrato**: MORDE explícito para `"Read"` ≠ `"read"` (`s2-pointer-mode.test.ts:29`).
- Redundância cosmética (`mode:"annotate"` dentro de `annotate_reserved`) é estilo de código, fora do que este gate julga.
