## 1. Pergunta central: o gráfico mente sobre o dado?

**Não — porque este módulo não tem dado para mentir sobre.** `s2-pointer-mode.ts` declara:
(a) o enum `PointerMode = "read"|"annotate"`, (b) a ordem de três camadas (`plot < overlay <
crosshair`, checada por posição via `assertOverlayIsSandwiched`), (c) `resolvePointerAction(mode,
input)`, que decide se clique/Espaço travam o crosshair. **Zero timestamp, zero série, zero
candle, zero OI/CVD, zero unidade, zero I/O** — confirmado por grep:

```bash

```
`[MEDIDO 2026-09-03]`, consistente com a alegação do módulo de cumprir `ADR-003` FR-1 ("charts não
faz I/O"). Nenhuma das armadilhas do meu mandato (âncora errada, interpolação silenciosa, unidade
trocada, LOCF indevido, selo/marcação desalinhada da série) tem superfície de ataque aqui: não há
série sendo lida, ancorada ou interpolada.

## 4. O que este julgamento NÃO cobre (e de propósito)

- **Legibilidade/acessibilidade da futura camada de overlay, motion do crosshair, carga
  cognitiva** — domínio de `ux-ui-mastery`, não meu (`docs/gate-de-design.md`). O README já
  declara "Gate de design — não aplicável: zero DOM, zero componente React"; essa alegação é
  plausível pelo grep acima, mas o veredito sobre ela pertence ao outro gate, não a este.
- **O comportamento real de `annotate`** (o que `swing_point`/`T-08.7` fará quando `Q11` for
  respondida) — declarado como **placeholder explícito** (`annotate_reserved`), não implementado.
  Isso é o correto do ponto de vista de fidelidade: em vez de **adivinhar** uma âncora ou tipo de
  marcação agora, o módulo recusa (lança erro tipado para valor fora do enum) e devolve um valor
  distinto e nomeado — a decisão errada aqui seria fingir que `annotate` já faz algo. Quando
  `T-08.7` vier, a chave completa de `<Anotacao>` (`SPEC-001:275-277` — inclui `cvd_anchor` e
  `quantity_field`, que são exatamente os dois campos onde uma âncora errada custaria dinheiro)
  terá de ser ligada por aquela task, não por esta — fora do escopo aqui, e corretamente deixado
  fora.
