## Achados de ambiente/teste, nomeados

Dois achados do próprio dublê `fakeredis`, medidos isoladamente com as classes cruas de `T-07.4`
(sem nenhum código deste adapter envolvido), e contornados na suíte em vez de escondidos:

1. `RedisStreamConsumerGroup.read_pending` sobre um Pending Entries List **já vazio** trava
   (nunca retorna). `test_redis_stream_bus.py` nunca exercita essa forma.
2. Chamar `ensure_group()` **duas vezes** (criação + "restart") imediatamente antes de
   `read_pending` sobre um PEL **não-vazio** corrompe a conexão do mesmo jeito, mesmo com uma
   entrada real para entregar.

Nenhum dos dois é defeito deste adapter — `RedisSeriesWriteQueue` nunca chama `ensure_group` em
produção (quem constrói o `RedisStreamConsumerGroup` decide isso fora dele). A suíte usa
`_queue(address, ensure_group=False)` para o "restart" e confirma `ack` via `XPENDING` direto em
vez de `read_pending` sobre PEL vazio.
