## Achado fora do DoD — `pyyaml==6.0.3` como dependência de RUNTIME (não bloqueante, sinalizado)

**(a) A invariante "`[project].dependencies = []`" NÃO está escrita em nenhum ADR/SPEC/`CLAUDE.md`
como regra vinculante com falsificador.** Busquei em `docs/adr/*.md`, `docs/specs/*.md`,
`CLAUDE.md` e `docs/decisoes-do-owner.md`: a única citação formal é
`docs/adr/ADR-014-motor-de-f0-enumeracao-de-verdict-e-testemunha-por-fonte.md:112`, que MEDE o
fato (`grep -n '^dependencies' backend/pyproject.toml` → `dependencies = []`) como argumento a
favor de manter SQLite em vez de Postgres — não como regra que proíbe adicionar dependência de
runtime em geral. `harness rules list --severity block` (n=7) também não tem regra sobre
dependências. **Conclusão: é padrão observado até agora (reforçado explicitamente em
`T-07.4`/`fakeredis`, que ficou dev-only "para não adicionar dependência de runtime"), não regra
escrita com dono e falsificador.** Por isso registro como observação não bloqueante, não como
`NEEDS_FIX` — mas destaco para revisão humana porque é a PRIMEIRA quebra desse padrão desde
`T-01.6`.

**(b) A citação do handoff/builder de que `SPEC-001` fixa YAML confere** —
`docs/specs/SPEC-001-plataforma-dados.md:242`: `` instrument_alias ( de, para, effective_from,
evidence_url )       # YAML versionado ``. O comentário em `backend/pyproject.toml:47-53` cita
essa mesma linha corretamente.

**(c) Parsing manual de YAML como alternativa: viável, mas o builder tem razão em rejeitá-lo.**
O documento real é trivial (`{"aliases": [...]}`, 4 campos string/data por item, sem âncoras,
sem multi-documento, sem tipos exóticos), então um parser de subconjunto seria pequeno — mas
"pequeno" não é "correto contra a gramática real": PyYAML já resolve corretamente casos que um
parser ad-hoc erraria sem testar (ex.: `effective_from` sem aspas parseado como `datetime.date`
pelo YAML 1.1 core schema, coberto por
`test_from_raw_accepts_a_date_object_pyyaml_already_parsed`, e por escaping de string com
`:`/`#` dentro de `evidence_url`, uma URL). Trocar uma biblioteca auditada, pin exato
(`==6.0.3`), por um parser próprio não testado é o débito técnico que o `pyproject.toml` já
argumenta contra, e concordo com o argumento — mas ele não substitui a resposta a (a): decisão de
arquitetura que quebra um padrão de 6 tasks (`T-01.6`→`T-07.9`) merece uma frase do owner ou um
ADR curto, não só um comentário de `pyproject.toml`, mesmo sendo um bom comentário.
