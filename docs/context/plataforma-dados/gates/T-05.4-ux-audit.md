## O que NÃO foi encontrado — checado e limpo

- **H5** (prevenção de erro): `findSlotAt` reprova com `RangeError` para grade vazia e para
  consulta desalinhada com a grade nativa — nenhum `NaN`/`undefined` silencioso passa adiante
  para um futuro renderizador.
- **H6** (reconhecimento > memorização): a API devolve `observedBucketStartMs` (geometria) E

  precisa recordar qual dos dois usar onde; o comentário do arquivo (`D5.1`/`D5.2`) já resolve
  essa ambiguidade uma vez, na fonte.
- **H3** (controle e liberdade): não aplicável — não há estado de UI, navegação nem undo
  neste módulo.

Não tenho navegador; nada abaixo foi verificado visualmente, só inferido da ausência de

  então a informação está disponível — falta ver se a UI futura de fato a usa).
- **[NÃO SEI]** se a interação do crosshair terá equivalente de teclado/toque (WCAG 2.1.1 /

- **[NÃO SEI]** timing/easing de qualquer transição da linha-guia — nenhum código de
  motion existe aqui.

**Estes cinco pontos não são condição desta task** (ela não deveria conter UI, e não
contém) — são a lista que este mesmo gate (`ux-ui-mastery`/`charts`) precisa reabrir quando a
task de `web` que consome `s2-absence-policy.ts` for despachada, porque só ali existirá algo
para de fato auditar visualmente.
