**Decisão de desenho, e por quê:** a chave B2 é extraída do `raw` (`json.loads` + os cinco campos

simular um daemon contínuo: ele é o mecanismo que um processo real chamaria, testado sobre fakes
que registram a ORDEM dos eventos (`new_opened → new_message_read → old_closed`), não só o
resultado.

## 2. O falsificador — os casos que a proteção REJEITA

**B3 (a colisão é detectada, não sempre-zero):**

```
test_the_falsifier_removing_the_duplicate_makes_the_collision_disappear
```

Com a duplicata (`FRAME_A` + mesma chave via `FRAME_A_DUP`, campos fora de B2 diferentes):
`DailyCollisionCount(total_events=1, collisions=1)`. Removendo a duplicata:
`DailyCollisionCount(total_events=1, collisions=0)`. Sem este par, um contador que sempre
devolvesse `collisions=0` passaria no primeiro teste sozinho por acidente.

**B1 (a ordem é exigida, não sugerida):**

```
test_require_overlap_rejects_the_old_source_closing_first
```

`ReconnectionHandoff(new_first_message_at=5.0, old_source_closed_at=4.9)` levanta
`ReconnectionGapError`, citando `ADR-004 B1` na mensagem. A aceitação do limite
(`old_source_closed_at == new_first_message_at`) é testada separadamente — overlap de duração
zero ainda é overlap, não buraco.

**A chave ignora ruído fora de B2:**

```
test_extract_ignores_fields_outside_the_declared_five
```

`FRAME_A` e `FRAME_A_DUP` diferem em `ap`/`z`/`X`/`f`/`o`/`E` e produzem a MESMA
`ForceOrderNaturalKey` — prova estrutural de que nenhum campo fora dos cinco declarados vaza para
dentro da chave.
