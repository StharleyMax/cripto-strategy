## Resumo dos 4 predicados (D1–D4 da ADR)

1. **`D1` habilitação por múltiplo de grade** — `classify_grid_multiple(panel_grid_ms, native_grid_ms)`, 3 estados nomeados (`MULTIPLE_OF_NATIVE`/`UPSAMPLING`/`NON_MULTIPLE`), nunca um booleano só — `CA-F4-4`.
2. **`D2` colisão de disco em px** — `classify_disc_layout(width_px, native_grid_ms, window_ms, radius_px, ring_px)`, geometria pura, `radius_px`/`ring_px` como parâmetro (nunca constante interna) — `CA-F4-5`.
3. **`D3` bucket em formação** — tipo-soma `Bar = FinalBar | InProgressBar`, sem campo `high`/`low`/`close` no estado em formação (`high_so_far`/`low_so_far`/`last`) — `CA-F4-19`.
4. **`D4` eixo Y único** — `SingleAxisSeries{denom: str}`, um único campo, sem forma que represente dois `denom` ao mesmo tempo; `switch_denom` substitui, nunca funde — `CA-F4-13`.

## Achado — numeração, não código

`D8.12`/`CA-F4-5` publica duas frases que não reconciliam sob a mesma leitura de "r": a desigualdade
compacta `2r+2 <= espaçamento_px` com `r=4` dá limiar em `10h`; o exemplo numérico do mesmo parágrafo
("disco r=4 com anel de 2px = 12px") dá limiar em `8,3333h` — que é o número que o próprio DoD publica
como `~8,33h`. Implementei a leitura que reconcilia (`2×(radius_px+ring_px) <= espaçamento_px`),
registrado na ADR §"Achado" com a conta: `1200×300.000/30.000.000 = 12`. Não editei `PRD-001`/plano `08`
— a redação ambígua continua lá, é decisão do dono daqueles documentos.

## Números citados, com o comando

```
1200 * 300000 / 86400000 = 4.1666...   # espaçamento_px, janela 24h — bate com PRD-001:652
2 * (4 + 2) = 12                        # min_required_px — bate com "disco r=4 anel 2px = 12px"
1200 * 300000 / 12 = 30000000 ms = 8.3333h   # limiar — bate com "~8,33h" do PRD-001/plano 08
2*4 + 2 = 10 -> janela = 36000000 ms = 10h    # leitura alternativa, NÃO bate com 8,33h publicado
```
Calculadora, sobre os números já publicados em `PRD-001:651-666` `[DOC]`; nenhuma medição nova.
