## O que fica registrado para a task que for renderizar (não bloqueia esta)

1. **Rótulo de mismatch não deve depender só de texto solto na tela** — já é bom que
   `describeAnnotationOnReopen` devolva `label` como STRING (não só uma flag booleana +
   cor), o que evita o anti-padrão "cor como único canal" (WCAG 1.4.1) antes mesmo de existir
   pixel. Quando a tela nascer, manter o texto visível, não escondê-lo atrás de hover/tooltip
   apenas.
2. **Não deixar a exceção de `resolvePriceSource`/`MissingPriceUseError` vazar crua para o
   operador** — capturar e traduzir para copy pt-BR (linha 8 da tabela de fronteira) na
   camada que efetivamente for renderizar.
3. **`price_source`/`price_use` no rótulo da tela** — quando `5.7` virar pixel, considerar
   que `klines_last`/`mark_price` são termos técnicos; avaliar se o operador final reconhece
   os dois nomes sem explicação adicional (H2/H6) — decisão de `ui-designer` na task que
   implementar a tela, não desta.

## O que este audit NÃO julga

Fidelidade do dado — se a tabela transcrita em `s2-price-source.ts` bate byte-a-byte com
`ADR-007`'s decision table e com `price_source_catalog.py` do backend é questão de
`quant-architect`, não deste gate. Também não julgo se `T-05.5` deveria ter incluído
renderização real para satisfazer literalmente "a marcação NÃO É REEXIBIDA" do `D5.5` (o
verbo sugere comportamento de tela) — isso é sobre completude de escopo/DoD, papel de QA/
arquiteto, não de interação do que existe.

**Merge:** sem impedimento do lado `ux-ui-mastery`.
