# T-08.6 — builder: motor `distribution`/`scan`/`firing_rate` (`ADR-020`)

Componente: `charts` (backend Python, `backend/src/modules/charts/`). Escopo: só backend — a
metade frontend do consequence de `ADR-020` (`histogram-recipe-bundle.ts`, renderizador em
`frontend/src/charts/`) e a rota HTTP (`infra`) **não fazem parte deste despacho** e não foram
tocadas.

## O que foi implementado

`backend/src/modules/charts/domain/`:

- `field_identity.py` — `FieldIdentity(metric, unit, denom)`, `ADR-020/D1`.
- `histogram_recipe.py` — `Interpolation` (5 membros, mesmo vocabulário de
  `threshold-spec-bundle.ts:55`), `HistogramRecipe` (`ADR-020/D6`, sem default em nenhum eixo),
  `DEFAULT_HISTOGRAM_RECIPE = {quantiles: (1,99), linear, pointMassMinShare: 0.01}`.
- `histogram.py` — `percentile` (as 5 interpolações de `numpy.percentile`, reimplementadas: zero
  dependência numérica no backend), `PointMass`/`Bin`/`Overflow`/`UniverseInfo`/
  `HistogramResult`, `compute_histogram` (`ADR-020/D2-D4`: massa pontual → quantis → bins +
  overflow, sobre população já elegível).
- `threshold_spec.py` — `AbsoluteSpec`/`PercentileSpec`/`RobustZSpec` (espelho Python de
  `frontend/src/app/threshold-spec-bundle.ts`, campo a campo, pinado por teste).
- `scan.py` — `evaluate_scan`/`ScanResult`: conta quantas observações elegíveis satisfazem um
  `ThresholdSpec` (`Absolute` compara direto; `Percentile` resolve o limiar por `percentile()`;
  `RobustZ` usa `(v-mediana)/(1,4826·MAD)`), `MinObsNotMetError` quando a população é menor que
  `min_obs`.
- `firing_rate.py` — `Window`, `InSampleFiringRate`/`WalkForwardFiringRate` (`ADR-020/D5`:
  `rate` é `None` POR TIPO no ramo `in_sample`).

`backend/src/modules/charts/use_cases/`:

- `compute_distribution.py` — `ObservationSource` (Protocol/porta) + `compute_distribution`.
- `run_scan.py` — reusa `ObservationSource`, chama `evaluate_scan`.
- `compute_firing_rate.py` — só constrói o ramo `in_sample` (`calib_window == eval_window`);
  `walk_forward` **recusa por nome** (`WalkForwardRuleNotDecidedError`), porque a regra é
  `T-08.8`, não esta task (`ADR-020/D5`, literal).

**Fora de escopo, e por quê (não esquecido — nomeado):** nenhum adaptador concreto de
`ObservationSource` (a query SQL contra TimescaleDB é "do builder [de uma task futura]",
`ADR-020/D7`); nenhuma implementação de `firing_rate` walk-forward (`T-08.8`); nenhum
`min_obs`/`n_obs`/dispersão de `z` por ponto (`T-08.7`); nenhuma rota HTTP (`infra`, `T-01.8`

## Bug achado pelos próprios testes (não escondido)

`HistogramRecipe.__post_init__` e `_bin_remainder` usavam `zip(..., strict=True)` sobre uma
lista e o seu deslocamento em 1 (`quantiles[1:]`/`sorted_edges[1:]`) — tamanhos DIFERENTES por
construção, e `strict=True` levanta `ValueError` sempre que o recipe tinha exatamente o mínimo
de 2 quantis (o próprio `DEFAULT_HISTOGRAM_RECIPE`). Pego na primeira rodada de
`pytest tests/charts` (6 erros de coleta, todo import de `histogram_recipe` quebrava).
Corrigido para `strict=False` nas duas linhas — o comprimento desigual É o desenho, não um erro
a proteger.
