## Resumo das cinco decisões (D1–D5 da ADR)

1. **Idade nunca é campo de tipo pooled/agregado** (`Observation`/`Fired`/`Bin`/`HistogramResult`/
   `ScanResult`) — ausência por OMISSÃO do campo, não por `None`. Um futuro tipo estreito
   `CurrentReading{instrument_id, value, age: EdgeAge}` (não implementado) seria o único lugar onde
   idade poderia existir, porque só ele representa UM ponto na borda direita de um instrumento.
2. **`ADR-006/D4` (invariante `limiar_atraso <= asof_max_staleness_ms`) é REUSADO de
   `sentimento.domain.as_of_accessor.reject_delay_threshold_above_staleness`** (já implementado,
   `as_of_accessor.py:343-369`, já por série) — `charts` nunca ganha uma constante de atraso própria.
3. **`denom` é sempre verbatim** (`FieldIdentity.denom`, `ADR-020/D1` intocado); o sentinela
   `"contratos (multiplicador não resolvido)"` para os 20 símbolos de `baseAsset` numérico é ato de
   `sentimento` (catálogo), nunca inferência por regex dentro de `charts` — a recusa de comparação
   cross-símbolo (`D8.18`) já é consequência estrutural de `FieldIdentity` ser chave frozen/hashable.
4. **Zero seleção é informação**: `ObservationSource.observed_values` nunca recebe `ThresholdSpec`
   (a população é fixada antes do limiar); nenhum `use_case` de `S4` faz retry condicionado ao próprio
   resultado. Generaliza o isolamento que `ADR-022/D4` já construiu para `z_dispersion`.
5. **`S4` é retrospectiva por assinatura**: nenhum `use_case` aceita "agora"/"até o presente" implícito
   nem contém laço de polling — `Window.end_ms`/`knowledge_time_ms` são sempre explícitos, até uma ADR
   futura reabrir isto nomeando que a rampa de `T-07.7` sustenta o custo.
