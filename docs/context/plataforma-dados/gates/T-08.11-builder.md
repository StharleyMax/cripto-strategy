## Mutação — os três falsificadores provados, não só afirmados

1. **Zero tick-level field**: `assertValidBucketEnvelope is a MUTATION guard` — envelope limpo
   passa, ganha `quantity`, reprova citando o nome do campo.
2. **`seq` monotônico / lacuna sem relógio**: `LiveSeqGapTracker: MUTATION` — sequência 1,2,4
   (pulando 3) é reportada com `gapDetected: true, missedCount: 1`, sem nenhum input de tempo no
   teste; `LiveSeqGapTracker throws when seq repeats/goes backward` prova que repetição ou
   regressão são tratadas como quebra de invariante (lança), distinta de lacuna (reporta).
3. **Taxa ≤ `max(1 Hz, 1/TF)`**: `LiveEnvelopeRateGuard: MUTATION` — fluxo saudável a exatamente
   60s de intervalo passa, ganha uma chegada a +500ms da anterior, reprova.

Achado durante a própria escrita do teste, corrigido antes de fechar: `decodeBucketEnvelope`
originalmente estreitava o payload bruto para os 6 campos conhecidos ANTES de checar campos de
tick — um campo de tick aninhado num campo desconhecido (`{ trade: { price: "…" } }`) seria
descartado pelo narrowing e nunca alcançaria `assertNoTickLevelFields`. Corrigido: o gate roda
sobre o payload BRUTO primeiro. Teste que capturou:
`decodeBucketEnvelope REFUSES a nested tick-level field` (falhou antes da correção, passa depois).
