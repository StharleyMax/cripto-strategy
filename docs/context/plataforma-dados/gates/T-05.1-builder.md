## Correção pós-QA rodada 2 (2026-09-02) — 2 formas fechadas por AST, 2 declaradas fora de escopo

QA rodada 2 (`T-05.1-qa.md`, seção "RODADA 2", veredito `NEEDS_FIX`) plantou 6 sondas próprias
e achou que o seletor `esquery` `ImportExpression[source.value=/.../]` (a correção anterior)
só lê `.value`, atributo que só existe em nó `Literal` — 4 formas escaparam com `rc=0`,
`ruleId: []`: template literal puro, template literal interpolado, concatenação de string,
`require(...)`.

**As 4 se dividem em 2 classes, tratadas de forma diferente — julgamento de arquitetura, não
correção uniforme:**

**Classe 1 — fechável por AST, fechada.** Template literal SEM interpolação
(`expressions.length === 0`) tem a string inteira em `quasis[0].value.cooked`, tão resolvível
quanto `Literal.value`; `require(...)` com argumento `Literal` é uma `CallExpression` tão
resolvível quanto `ImportExpression` com `Literal`. Dois seletores `no-restricted-syntax`
novos, espelhados nos 2 blocos de `frontend/eslint.config.mjs`:

```js
"ImportExpression[source.type='TemplateLiteral'][source.expressions.length=0]" +
  "[source.quasis.0.value.cooked=/.../ ]"
"CallExpression[callee.name='require'][arguments.0.value=/.../ ]"
```

Verificado a viabilidade do seletor ANTES de escrever a regra, via `esquery.match` isolado
(não supondo que o path com índice de array funciona):

```
$ node -e "esquery.match(ast_de_import_template, esquery.parse(\
  'ImportExpression[source.quasis.0.value.cooked=/charts/]'))"   → 1 match  [MEDIDO 2026-09-02]
$ node -e "esquery.match(ast_de_require, esquery.parse(\
  'CallExpression[callee.name=\"require\"][arguments.0.value=/charts/]'))" → 1 match [MEDIDO 2026-09-02]
```

Probes reais plantados e removidos manualmente antes de tocar o teste (`git status --short`
confirmou árvore limpa depois):

```
$ node_modules/.bin/eslint src --format json   # com 4 probes (2 direções x 2 formas)
src/app/_qatest_bare_template.ts     ["no-restricted-syntax"]
src/app/_qatest_require.ts           ["@typescript-eslint/no-require-imports","no-restricted-syntax"]
src/charts/_qatest_bare_template.ts  ["no-restricted-syntax"]
src/charts/_qatest_require.ts        ["@typescript-eslint/no-require-imports","no-restricted-syntax"]
```
`[MEDIDO 2026-09-02]`. `require` dispara 2 regras (a nova + a regra padrão `typescript-eslint`
que já reprova `require` em geral) — o teste usa `.includes("no-restricted-syntax")`, não
`deepEqual`, para não depender de quantas outras regras também disparam.

**Classe 2 — NÃO fechável por análise estática, declarada como limite permanente.**
Concatenação (`BinaryExpression`) e template interpolado (`TemplateLiteral` com
`expressions.length > 0`) não têm `.value`/`.cooked` que nomeie o alvo ANTES do programa
rodar — resolver exigiria interpretar o programa, que nenhum linter estático faz. Confirmado
que os 2 probes de controle continuam sem casar (nenhuma regra nova os alcança):
`import("../charts/" + x)` e `` import(`../charts/${x}`) `` seguem `ruleId: []` após a
correção — mesmo resultado que QA mediu antes. Declarado no `ADR-003` addendum
(2026-09-02, "mais 2 formas fechadas... 2 declaradas fora de escopo") como limitação
estrutural aceita, não como TODO — mesmo tom da lacuna de alias de bundler já registrada.

`frontend/src/charts/eslint-boundary.test.ts` ganhou 2 testes morde+cala novos (bare template
literal, `require`), cobrindo só as 2 formas fechadas — as 2 fora de escopo não têm probe,
porque morde+cala não afirma cobertura que o contrato não tem.
