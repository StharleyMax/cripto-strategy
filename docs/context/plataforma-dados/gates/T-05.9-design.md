## O que foi verificado, com o comando/leitura que produziu cada achado

1. **`D5.8` é transporte, não pixel.** O critério do DoD (`docs/plans/SPEC-001-plataforma-dados/05_fatia_visivel.md:36`)
   é *"contar mensagens e inspecionar payload"* — verificação de taxa e de campo, não de tela. `ADR-005/D1`
   decide a rota (HTTP endereçável por conteúdo para histórico, SSE só na borda ao vivo) e nenhuma das
   duas introduz superfície visual nova: `S2` já declara `içamento` de 3 níveis (sessão/painel/número) e
   "idade só na borda direita do tempo" — exatamente a consequência de `D3`/`D2` desta ADR
   — `[DOC: STITCH_CONTEXT.md §4.1 tabela "conteúdo da S2-mínima"; ADR-005 §Consequência]`.

2. **`S2` canônica não mudou e não precisa mudar.** `get_project` (`projects/9264019151773162472`),
   2026-09-02: `screenInstances` ainda são as 3 telas documentadas, `8174234965cd4ffbacfb7b2a0a61a427`
   continua a `S2` canônica, `updateTime: 2026-08-28T14:55:11Z` — idêntico ao registrado em
   `STITCH_CONTEXT.md` §4.1.0/§4.1.3. Nenhuma edição foi feita nesta task (`R4`, `R5`, `R7`: mudança em
   `S2` seria BLOCKER, e não houve necessidade de propor nenhuma).

3. **Vocabulário de domínio já estabelecido — usado como referência para o builder, não como decisão
   minha.** `frontend/src/app/knowledge-time-bundle.ts` (produto de `T-05.8`) já fixou a convenção de
   nomear parâmetros de URL por campo de domínio, não por abreviação: `symbol`, `from`, `to`, `mode`,
   `asOf` (renomeado de `t` pelo achado do `ux-audit` de `T-05.8`, H2/H4/H6). `ADR-005/D1` chaveia a
   resposta HTTP por `(series_key_id, symbol, interval, janela, knowledge_time, bar_policy)` — os nomes
   já existentes no domínio (`SeriesKey`, `bundle`, `knowledge_time`) casam com essa convenção; não há
   abreviação nova a cunhar aqui.

## O que este gate NÃO pôde auditar, e por quê — registrado, não escondido

**O módulo de transporte HTTP em si ainda não existe** — `find frontend/src -type f` (2026-09-02) não
lista nenhum arquivo de transporte/fetch para histórico; `tasks.toml:697` marca `T-05.9` como
`status = "todo"`. Isto é **antes** do `/build`, não depois — diferente de `T-05.8`, cujo `ux-audit`
revisou código já escrito. **Não há payload/endpoint/mensagem de erro real para rodar heurística de
Nielsen contra.** Por isso este gate fecha a pergunta de **arquitetura de tela** (não há nenhuma) e
**não** substitui o audit de nomenclatura que `T-05.8` fez — esse audit tem de rodar **depois** do
`/build`, sobre o código real, pelo mesmo motivo do handoff: nomenclatura pública é retrofit caro depois
de publicada.

**Recomendação registrada para quem construir e para o `ux-audit` seguinte, não uma decisão travada:**
usar `knowledge_time`/`bundle`/`SeriesKey` (nomes já em vigor) nos parâmetros do endpoint e da chave de
cache, em vez de abreviação nova — é a mesma correção que `T-05.8` já pagou uma vez (H4, consistência com
o próprio código ao redor). `[NÃO SEI]` se o builder vai seguir; falsificador: se o módulo novo nomear o
parâmetro de tempo de forma diferente de `knowledge_time`/`asOf`, é o mesmo defeito de H2/H4/H6 que
`T-05.8-ux-audit.md` já documentou, reincidindo.

errado) e não é desta task consertar um gate já fechado de `T-05.8`; registro para quem for hackear a
árvore de citações.
