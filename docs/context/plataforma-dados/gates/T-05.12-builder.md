**Decisão de builder não coberta pelo gate**: o gate não fixa de onde `src.main` lê o

`src.main` (`SqliteIngestRecordStore.__init__` só liga um `Path`; a leitura trata arquivo/tabela
ausente como zero linhas).

`uvicorn` 0.52.4 (`hasattr(uvicorn.Config(...), "install_signal_handlers")` → `False`) — a
versão pinada já detecta thread não-principal sozinha (`Server.capture_signals`, checa
`threading.current_thread() is threading.main_thread()`) e pula a instalação do handler. Omiti
a linha; documentado no docstring do teste.

```

grep -niE 'SELECT|FROM |psycopg|sqlite3' backend/src/api/routes/ingest_health.py
```

**O grep do DoD, LIDO LITERALMENTE, devolve 4 linhas — TODAS `from X import Y` do Python**
(`from __future__ import annotations`, `from fastapi import …`, `from src.api.dependencies
import …`, `from src.modules.sentimento.use_cases.ingest_health import …`). `FROM ` (case-
insensitive) casa com a sintaxe de import do próprio Python, não só com SQL — é um falso
positivo do padrão, não uma linha de SQL. Zero das 4 é `SELECT`/`psycopg`/`sqlite3` e zero é uma
cláusula SQL `FROM`. Handler não toca em `sqlite3`, `psycopg` nem monta uma query própria —
único ponto de leitura é a chamada a `ingest_health_query(source)`.
