## O que foi verificado, e como

1. **Falsificador do ADR-022 reproduzido de forma independente** (script Python próprio, sem
   reusar o teste do builder), com dois cenários:
   - população de 2 (`BTCUSDT` n_obs=2016, `ALTUSDT` n_obs=300, `min_obs=576`): `n_total=1`,
     `n_excluded_min_obs=1`, `Insufficient(instrument_id="ALTUSDT", n_obs=300,
     min_obs_required=576)` presente, nenhum `Fired`/`NotFired` para `ALTUSDT`.
   - população de 5 (4 sobreviventes + 1 `Insufficient`): confirma que **não é tudo-ou-nada** —
     os 4 sobreviventes recebem veredito `Fired`/`NotFired` normalmente (`n_fired=1`), só o
     instrumento com `n_obs` insuficiente é excluído.
   - Também bate com `test_scan.py::test_adr_021_falsifier_mixed_n_obs_excludes_the_underobserved_symbol_not_the_aggregate`,
     que roda o mesmo caso e passa.

2. **`z_dispersion`/telemetria nunca é lida por função de decisão** — grep + introspecção AST
   próprios (não confiei no relato): `_fires(value, population, spec)`, `_robust_z(value,
   population)`, `_compare(value, op, threshold)`, `evaluate_scan(observations, field, nature,
   universe_declared, n_universe_resolved, spec)` — nenhuma assinatura contém `z_dispersion`.
   `_z_dispersion()` é chamada só no final de `evaluate_scan`, depois de `n_fired`/`per_observation`
   já estarem prontos (`scan.py:306`), nunca alimenta `_fires`/`_robust_z` de volta.

3. **`histogram.py` intocado** — `git diff master --stat -- backend/src/modules/charts/domain/histogram.py`
   devolve 0 linhas. `compute_distribution.py` só projeta `.value` antes de `compute_histogram`
   (linha 90), confirmando `ADR-022/D5`.

4. **União discriminada `Fired|NotFired|Insufficient`** — `Insufficient` não tem campo de valor
   (`dataclasses.fields` = `{instrument_id, n_obs, min_obs_required}`, testado em
   `test_insufficient_verdict_carries_no_value_field`); no cenário do item 1, `ALTUSDT` vira
   `Insufficient`, nunca um `NotFired` disfarçado (motivo do descarte é explícito, não implícito).
