## 1. Correção de premissa medida — o "precedente uvicorn"

O despacho pedia para **confirmar** que uvicorn é o precedente do `anything_monorepo`. Medido:

```
grep -nE 'fastapi|uvicorn|granian' anything_monorepo/backend/pyproject.toml
# -> fastapi = "^0.139" ; uvicorn = {version="^0.32", extras=["standard"]} ; granian = "^2.7.9"
grep -n 'CMD' anything_monorepo/backend/Dockerfile
# -> CMD ["granian", "--interface", "asgi", ..., "src.main:asgi_app"]
cat anything_monorepo/backend/src/main/__main__.py   # dev launcher tambem usa Granian.serve()
grep -rln 'uvicorn' anything_monorepo --include='*.py'   # -> 0 arquivos
```

**A premissa estava parcialmente errada**: o vizinho serve produção E dev com **Granian**;
`uvicorn` está declarado no `pyproject.toml` e **nunca é importado por nenhum `.py`** — dependência
morta. O que É precedente real e vale copiar: `FastAPI(` mora em `src/main/__init__.py` (função
`create_app()`), e `src/api/` é raiz de rotas fora de `src/modules/`.

**Por que este repositório escolhe `uvicorn` mesmo assim, e não Granian nem o precedente**: DoD
D5.13 exige provar PELA REDE **sem subprocess** — subir o servidor ASGI **na mesma thread do
processo de teste**, com socket real. `uvicorn.Server` é desenhado para isso (`Config(...,
install_signal_handlers=False)` + `Server.run()` numa `threading.Thread`, padrão documentado da
própria ferramenta). Granian é um servidor Rust pensado para rodar como processo próprio (é assim
que o vizinho o usa nos dois ambientes) — não há precedente, no vizinho ou aqui, de embutir Granian
numa thread de teste. `uvicorn` bare (sem `[standard]`) é a escolha que paga o mínimo de disco.

## 5. Envelope exato (ADR-005/D6.1) — UM ponto de projeção, não dois

`IngestHealthReport.canonical_lines()` hoje serializa para **texto JSON-lines** (formato do CLI).
O envelope HTTP é **um objeto aninhado**, forma diferente. Para não duplicar a regra de coluna
(`INGEST_HEALTH_RUN_COLUMNS`/`INGEST_HEALTH_GAP_COLUMNS`, o `class`→`gap_class`, o
`janela_de_perda=None` em F0) em dois lugares — que seria a MESMA classe de defeito que
`ADR-008/DoD-1` existe para impedir, um nível acima do SQL —, a decisão é: **refatorar
`domain/ingest_record.py`** para que `_project_run`/`_project_gap` (hoje só produzem string JSON)
passem a ter uma etapa intermediária que devolve `dict`, reaproveitada tanto pelo CLI quanto por
um novo método público `IngestHealthReport.to_envelope() -> dict[str, object]` que monta
`{query, n_runs, n_gaps, runs: [...], gaps: [...]}` na ordem de coluna do contrato.

⚠️ **Isto toca `domain/`, e `domain/` não é minha superfície** — é a mesma classe de objeto que o
`quant-architect` julga (`ADR-008/D3` fixou as colunas). Não decidi por ele: a mudança proposta
é puramente estrutural (extrair dict de uma função que já existe, sem tocar contrato de coluna
nem de valor), mas o builder deve considerar looping o `quant-architect` se a extração parecer
tocar semântica, não só forma.

**Handler nunca serializa coluna por conta própria** — só chama `report.to_envelope()`. Isso é o
que faz D5.13c (zero SQL, ponto único) valer também no nível de projeção, não só no de leitura.

## 7. Bind — loopback, sem `deploy/`

`create_app`/`__main__.py` fazem bind em **`127.0.0.1`**, nunca `0.0.0.0` — diferente do vizinho
(que faz bind em `0.0.0.0` DENTRO do container, e o loopback é imposto pelo compose no host,
`127.0.0.1:8000:8000`). Aqui `deploy/` **não existe ainda** `[MEDIDO 2026-09-03 pela mesma
observação de abertura deste agente: `ls -d deploy` inexistente]`, então a única superfície capaz
de impor loopback hoje é o bind do próprio processo. Quando `deploy/` nascer (falsificador
`F-D6-5b`/plano `01` item `1.14`, que não é esta task), a topologia de container pode reabrir
esta escolha — registrado como dívida, não como decisão fechada de infra futura.

## 8. Teste PELA REDE (D5.13) — sem subprocess, sem TestClient

```
backend/tests/api/
├── __init__.py
└── test_ingest_health_route_over_the_network.py
```

Técnica — o mesmo idioma já usado em `backend/tests/sentimento/test_redis_stream_bus.py`
(`threading.Thread(daemon=True)` + bind real + `shutdown()` no teardown), adaptado de
`socketserver` para `uvicorn.Server`:

```python
config = uvicorn.Config(app, host="127.0.0.1", port=0, log_level="warning")
config.install_signal_handlers = False       # obrigatório fora da thread principal
server = uvicorn.Server(config)
thread = threading.Thread(target=server.run, daemon=True)
thread.start()
while not server.started:
    time.sleep(0.005)
port = server.servers[0].sockets[0].getsockname()[1]
...
conn = http.client.HTTPConnection("127.0.0.1", port, timeout=5)
conn.request("GET", "/ingest-health")
resp = conn.getresponse()
...
server.should_exit = True
thread.join(timeout=5)
```

**CALA** (processo de pé): `resp.status == 200`; `set(body) == {"query","n_runs","n_gaps","runs",
"gaps"}`; `set(body["runs"][0]) == set(INGEST_HEALTH_RUN_COLUMNS)` (15, `janela_de_perda` presente
e `None`); `set(body["gaps"][0]) == set(INGEST_HEALTH_GAP_COLUMNS)` (8, chave literal `"class"`,
nunca `"gap_class"`); nenhuma chave de `agg_id`/preço-por-trade/quantidade-por-trade em nenhum dos
dois (D5.8 com sujeito).

**MORDE** (processo derrubado): teste separado — `server.should_exit=True; thread.join()`, então
`http.client.HTTPConnection(...).request("GET", ...)` **tem que levantar
`ConnectionRefusedError`**, não uma asserção de payload. Fixture seeda 1 `IngestRun` (via
`tests/helpers/ingest_record_driver.build_run`, já existente) + 1 `IngestGap` através de
`SqliteIngestRecordStore.record_run`/`record_gap` num `tmp_path`, mesma técnica de
`test_ingest_health_query.py`.

`http.client` (stdlib) é o cliente — nunca `httpx`/`requests` (não declarados em
`backend/pyproject.toml`, e 5 dos 49 módulos de `infra/` já falam `http.client`
`[MEDIDO 2026-09-03, ref. do próprio task spec]`).
