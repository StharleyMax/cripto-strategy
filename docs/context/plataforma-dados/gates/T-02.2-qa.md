## 3. Escrutínio do achado de guarda arquitetural (`DECLARED_TOUCHERS`)

Verifiquei a alegação do builder linha a linha, não só a prosa:

- `quarantined_series_entry.py::available_at` é uma `@property` que devolve **sempre `None`** para
  linhas desta task (`quarantine.available_at_present` vem de `COINALYZE_ONE_SHOT_TERMS`, que fixa
  `available_at_present=False` — `quarantine_terms.py:57-63`).
- `sqlite_series_quarantine_store.record()` usa `entry.available_at` **apenas para persistir** na
  tupla do `INSERT` (linha 122) — não há nenhuma comparação contra um instante de decisão `t` em lugar
  nenhum do método. É write-path puro, mesma categoria de `provenance.reject_clock_skew` já declarada.
- `read_promoted()` filtra `available_at IS NOT NULL` dentro de uma **string SQL** (`_SELECT_PROMOTED`),
  nunca como atributo Python — confirmei rodando o próprio guard (`test_as_of_is_the_single_reader.py`)
  com o arquivo intacto: passa, e o scanner AST (`ast.Attribute`) genuinamente não alcança dentro de uma
  string, então não há nada que `read_promoted` devesse declarar.
- **Veredito: a correção é legítima, não é bypass do guard.** O módulo não computa "valor de uma série
  no instante `t`" em lugar nenhum — só grava um `NULL` estrutural e faz um filtro de presença
  (`IS NOT NULL`) para promoção, o que é uma categoria de operação diferente da que o guard existe para
  proteger (um segundo leitor de `as_of`). A entrada aditiva em `DECLARED_TOUCHERS` (só `record`, não
  `read_promoted`) está correta e é a mínima necessária — reproduzi eu mesmo, ao vivo: removi a
  entrada de `sqlite_series_quarantine_store.py` do dict (edição direta), rodei
  `.venv/bin/python -m pytest -q --no-cov tests/sentimento/test_as_of_is_the_single_reader.py` →
  **1 failed** (`AssertionError: Extra items in the left set:
  'modules/sentimento/infra/sqlite_series_quarantine_store.py'`), depois `git checkout --` no
  arquivo e confirmei `sha256sum` idêntico ao original (`57f02358…`) e a suíte voltando a
  **5 passed**. O achado do builder é real (reprovava sem a entrada) e a correção resolve a
  causa (falta de declaração do write-path), não é bypass sintomático.
