## Camada 2 — arquitetura declarada

### [WARNING] `s2-klines-loader.ts`/`s2-oi-loader.ts`/`s2-cvd.ts` fazem I/O real dentro de `charts`, contra `ADR-003` FR-1 — e o precedente citado para justificar isso é de outra classe de arquivo

`docs/adr/ADR-003-fronteira-charts-web.md:36`: **"FR-1 | `charts` não faz I/O. Zero `fetch`,
zero rota, zero `localStorage`. Toda entrada é argumento | um módulo de `charts` é testável
sem servidor e sem rede — e a S2-mínima é construível offline, que é o que F1 promete"**. O
mesmo texto está reforçado no comentário do `no-restricted-imports` de `D5.12`
(`frontend/eslint.config.mjs`): *"ADR-003 FR-1: `charts` does no I/O and knows no
route/session"*.

`frontend/src/charts/s2-klines-loader.ts:10` (`readFileSync`), `s2-oi-loader.ts:27,79-84`
(`readFileSync`/`existsSync`) e `s2-cvd.ts:32,124-149` (`readFileSync`) chamam I/O de disco
diretamente — e não são arquivos de teste (`*.test.ts`); são módulos de produção em
`frontend/src/charts/`, importados por `s2-panels.ts` (também produção, não teste), cujas
funções exportadas (`buildPricePanel`/`buildOiPanel`/`buildCvdPanel`/`buildS2Panels`) recebem
só `dataRoot: string` — a leitura de arquivo acontece DENTRO de `charts`, não é passada como
argumento já resolvido. Isso é o oposto literal de "toda entrada é argumento".

Cada um dos 3 arquivos cita o mesmo precedente para se justificar (`s2-oi-loader.ts:5-9`,
quase idêntico em `s2-klines-loader.ts:5-7`): *"the same precedent
`canonical-grid-sha256-proof.test.ts` already set for `T-05.1`... a task-specific loader
[stands] in the same role a test fixture loader does"*. **O precedente citado é de outra
classe de arquivo**: `canonical-grid-sha256-proof.test.ts` é um `.test.ts`, rodado só por
`node --test`/`npm run test:charts` — nunca importado por um bundle que `web` monte. `git ls`
confirma que, antes desta task, **nenhum arquivo `.ts` de produção (não-teste) em
`frontend/src/charts/` chamava `node:fs`** (`canonical-grid.ts`, `canonical-grid-chart-
consumer.ts`, `canonical-grid-accessor-consumer.ts`, `headless-chart.ts`, `axis-fidelity.ts`,
`synthetic-series.ts` — zero I/O em todos; só o `.test.ts` fazia leitura de fixture)
`[MEDIDO nesta revisão: grep -l readFileSync sobre esses arquivos → só o .test.ts casa]`. Os 3
novos loaders são os PRIMEIROS módulos não-teste de `charts` a chamar `node:fs`.

**Por que isto não é só estilo:** `node:fs` não existe em bundle de navegador. Se `T-05.3+`
importar `buildS2Panels`/`buildPricePanel` de `s2-panels.ts` para montar uma tela real em
`web` (o próximo passo natural, já que "S2-mínima" existe para isso), o bundle quebra em
tempo de build ou de execução no navegador — exatamente o modo de falha que FR-1 existe para
prevenir ("testável sem servidor e sem rede" pressupõe rodável sem Node por trás). Hoje isto
não quebra nada porque `test:charts` roda em Node (`node --test`), e nenhum ponto de montagem
em `web` foi criado nesta task (confirmado, ver Escopo abaixo) — mas o código como está
**não pode** ser importado por `web` sem reescrita, e nada no addendum da ADR nomeia essa
dívida.

**Não é achado mecânico** (nenhuma regra bloqueante do harness cobre I/O em TS —
`import-linter` não lê TypeScript, como a própria `ADR-003:75` já admite; `no-restricted-
imports` de `D5.12` restringe SÓ o sentido `charts`→`app`/`features`, não `node:fs`) — por
isso **WARNING**, não BLOCKER, e por isso nem o gate de QA nem o addendum da ADR o pegaram:
ambos mediram as 7 regras do harness + o D5.12 de import, não FR-1 de I/O.

**Correção concreta:** os 3 loaders deveriam expor só o parser puro (`parseKlinesCsv`,
`parseOiMetricsCsv`, `accumulateDayIntoTotals` — que já são puros, recebem texto) como API de
`charts`, e mover a chamada `readFileSync`/`existsSync` para fora de `frontend/src/charts/`
(um script de fixture, ou o futuro consumidor em `web`/Node que hoje ainda não existe) — a
mesma separação que `s2-panels.test.ts`/`s2-*.test.ts` já fazem ao ler fixture e chamar a
função pura. Alternativa: nomear explicitamente no addendum da ADR que estes 3 arquivos são
uma exceção declarada a FR-1, escopo "loader de fixture real, não API de renderização", com o
mesmo cuidado que a linha 11 da tabela de idioma do `CLAUDE.md` usa para exceções — hoje isso
não está escrito em lugar nenhum, nem no handoff, nem no addendum.
