## A descoberta que ampliou o escopo em 1 arquivo — e por quê

O DoD (`grep -rln 'from "node:' frontend/src --include='*.ts' | grep -v '\.test\.'` → rc=1,
zero, exceto `app/threshold-spec-bundle.ts`) exige **zero** arquivo com import `node:` nesta
árvore fora da exceção nomeada — e isso inclui `import { createHash } from "node:crypto"`, que
`fingerprint()` também usava (não é subprocesso, mas é `node:`). Remover só os 4 imports do
CLI teria deixado este arquivo na lista do grep, reprovando o próprio DoD que a task cita.
`T-05.16`/`ADR-005/D6.4` já fixam que `fingerprint()` tem de PERMANECER SÍNCRONA (proibindo
`crypto.subtle.digest`, que é `Promise`-returning por spec) — então a saída não podia ser
"trocar para Web Crypto". Criei `frontend/src/features/s1-console/sha256.ts`: SHA-256 puro,
sem dependência nova, síncrono por construção em qualquer runtime (Node ou browser).

Correção verificada em duas camadas independentes:
1. `sha256.test.ts` — 3 vetores PUBLICADOS FIPS 180-4 (`""`, `"abc"`, a mensagem de 2 blocos do
   NIST) + 1 caso UTF-8 vs UTF-16 + controles positivo/negativo.
2. `ingest-health-query-http.test.ts`'s `CALA F-D6-1`/`MORDE F-D6-1` — compara o `sha256` desta
   implementação contra `IngestHealthReport.fingerprint()` do backend Python REAL, sobre o
   MESMO estado, via rede loopback. **Passou** com o backend real (`.venv` do repo principal,
   linkado por conveniência nesta worktree).
