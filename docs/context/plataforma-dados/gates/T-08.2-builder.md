## 2. O que exatamente foi medido, porque uma definição vaga tornaria o número infalsificável

Para cada item renderizado, o erro é `|x_real − x_esperado|`, onde `x_esperado` é o mapa
**afim** de tempo para pixel calibrado nas **duas amostras extremas do próprio gráfico**:

```
esperado(t) = x(t₀) + (t − t₀) / (t_n − t₀) · (x(t_n) − x(t₀))
```

**Ancorar nos extremos do próprio gráfico é a escolha conservadora, e é deliberada:** cancela
todo offset, padding e margem direita que a biblioteca aplica, de modo que um erro não-nulo só
pode vir da **não-linearidade** do mapa tempo→pixel. Uma definição ancorada numa origem externa
reportaria o padding da biblioteca como erro — isso seria espantalho, porque padding não faz o
eixo mentir sobre `event_time`.

**Ressalva que limita a afirmação, escrita porque ela limita:** por construção os dois extremos
têm erro exatamente 0, então o pior caso é sempre encontrado **estritamente dentro** da janela,
e o número publicado é um **limite inferior** do que uma definição ancorada externamente
reportaria — nunca inflado.

Publicado é o **pior caso**. A média aparece como contexto (`5,71e-14 px` em A, `19,216 px` em
B **na semente publicada** — 6,122 a 19,216 px sobre `n=5`, §3.1) e **não é o critério** — há teste de unidade que pinta exatamente esse caso: média abaixo da
tolerância com veredito FORA.

## 3. O achado, e ele é maior que o veredito

**O eixo do Lightweight Charts indexa por posição ordinal do slot, não por `event_time`.**
Sobre uma grade de 1 m completa, "ordinal" e "linear no tempo" são **a mesma função**, e por
isso o cenário A dá zero-de-float. Assim que a grade tem buracos, as duas funções divergem, e
divergem muito: **na semente publicada, 36,390 px — 73× a tolerância** — no pior ponto
(`2025-01-01T13:47:00Z`, série candle, `x` real `689,245 px` contra `652,855 px` esperado).
**Esse número é de UMA semente, e a §3.1 publica a faixa das cinco** — a divergência é
robusta; a magnitude dela não é.

**Por que isso não é hipotético:** a cobertura de 20,0% do cenário B não foi inventada — é o
número que o **próprio plano 08 já mediu** para o timeframe de 1 m (`D8.11`: *"Cobertura: 1m
**20,0%** · 5m 100% · 15m 100% · 60m 99,9% · 240m 99,4% · 1440m 100%"*).

**O que o cenário B NÃO afirma, e a distinção importa:** a **forma** dos buracos é sintética e
semeada (LCG determinístico, `seed = 20260829`), e este spike **não** afirma que ela reproduz a
distribuição real de lacunas. Ele afirma que **naquela cobertura alvo, e em toda semente
testada**, o eixo ordinal deixa de concordar com `event_time`. **Ele NÃO afirma por quanto** —
a magnitude é propriedade da semente, não da cobertura, e a §3.1 mede o quanto ela varia.

> ⚠️ **A versão anterior desta frase terminava em *"e por quanto"*, e isso era extrapolação
> minha** — feita na frase seguinte à ressalva que existia para impedi-la. Achado por `/qa`

### 3.1 O que é robusto e o que NÃO é — `n=5` sementes, mesma cobertura alvo

O corpo da sonda vai **inteiro** aqui, e não como caminho em `/tmp`: um número cujo comando
mora fora do repositório não reproduz para o próximo leitor — que é a mesma classe de defeito
que `F-1` e `F-2`. Ela usa o **caminho de código do runner** (`buildSparseGridWorkload` ->
`collectAxisCoordinates` -> `measureAxisFidelity`); não é um modelo do gráfico, é o gráfico.

```bash

const base = "./src/charts/";
const { buildSparseGridWorkload, CANDLE_COUNT } = await import(base + "synthetic-series.ts");
const { collectAxisCoordinates } = await import(base + "headless-chart.ts");
const { measureAxisFidelity } = await import(base + "axis-fidelity.ts");
for (const seed of [20260829, 1, 42, 987654, 20260830]) {
  const w = await buildSparseGridWorkload(0.2, seed);
  const { samples } = await collectAxisCoordinates(w);
  const r = measureAxisFidelity(samples);
  const cov = ((w.candles.length / CANDLE_COUNT) * 100).toFixed(2);
  console.log(`seed=${seed} candles=${w.candles.length} cobertura=${cov}% ` +
    `pior=${r.worstErrorPx.toFixed(3)}px (${(r.worstErrorPx / 0.5).toFixed(1)}x) ` +
    `media=${r.meanErrorPx.toFixed(3)}px`);
}'
# seed=20260829 candles=314 cobertura=21.81% pior=36.390px (72.8x) media=19.216px
# seed=1        candles=294 cobertura=20.42% pior=27.333px (54.7x) media=7.664px
# seed=42       candles=258 cobertura=17.92% pior=13.664px (27.3x) media=6.122px
# seed=987654   candles=276 cobertura=19.17% pior=27.753px (55.5x) media=11.300px
# seed=20260830 candles=286 cobertura=19.86% pior=27.254px (54.5x) media=12.088px
```

### 4.2 Mutação no INSTRUMENTO — e ela pegou um FALSO VERDE REAL, produzido aqui

**A primeira versão desta medição publicou `0,000 px` e estava errada.** `fitContent()` e
`setVisibleLogicalRange()` **não mudam nada de forma síncrona** — enfileiram uma invalidação
aplicada dentro do ciclo de desenho movido a `requestAnimationFrame`. Lendo as coordenadas sem
deixar o ciclo rodar, o gráfico responde de um modelo ainda com os **defaults**: `barSpacing = 6
px`, faixa alinhada à direita, **1.440 barras espalhadas por ~8.634 px numa pane de 1.200 px**.
Nessa geometria toda barra fica a um número **inteiro** de pixels da vizinha, o erro sai
`0,000 px`, e o DoD parece satisfeito — **avaliando um gráfico 7× mais largo que a viewport,
num espaçamento onde arredondamento sub-pixel não pode ocorrer.** Ou seja: mediu-se exatamente
o que `D8.19` existe para não deixar passar.

A correção tem duas partes, e a segunda é a que dura: (a) `flushFrames()` deixa o ciclo rodar;
(b) `assertViewportFitted()` **RECUSA a corrida** se o fit não aterrissou.

```bash
# mutação: remover as chamadas de flushFrames() de headless-chart.ts
npm --prefix frontend run spike:axis   # rc=3
# RECUSA: nao consegui medir — o eixo NAO coube na viewport: barSpacing = 6 px para 1440
# slots em 1200 px de pane (esperado ~0.8333 px). O ciclo de desenho nao aplicou o fit, e
# medir aqui devolveria o numero de um grafico com ~8640 px de largura, nao de 1200 px.
```

`[MEDIDO 2026-08-29: rc=3 com a mutação, rc=0 sem ela]`. `rc=3` é *"não mediu"* e é **diferente**
de `rc=1` (*"mediu e reprovou"*) — a mesma semântica de `backend/scripts/lint.sh` e de
`scripts/verify.sh`.

### 4.2-bis A guarda agora REGRIDE — a mutação de 4.2 virou teste (`F-3`, ciclo 2)

**A prova de 4.2 era manual e rodava uma vez.** `assertViewportFitted` — a única coisa que

recusa a pane de largura zero — cujo `drift` é `NaN`, e `NaN > 0.02` é **falso**, então sem
esse ramo um modelo não-dimensionado passaria como *"coube"*.
