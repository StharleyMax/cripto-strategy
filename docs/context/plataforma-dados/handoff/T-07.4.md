- **Redis Streams + consumer group para TODO consumidor com estado — nunca Pub/Sub.**
- **D7.10**: reiniciar o acumulador de CVD (ou qualquer consumidor com estado acumulado) ⇒ **nenhuma
  mensagem perdida**.
- **Razão, e é a que o teste tem que provar**: Redis Pub/Sub é **at-most-once por doc** — a doc da
  própria Redis diz *"the message is forever lost"* se não houver subscriber conectado no momento do
  publish. Um acumulador de soma acumulada (CVD é exatamente isso) **não sobrevive** a essa perda —
  cada mensagem perdida é um erro permanente e crescente no acumulado, nunca corrigido.
- O teste central desta task: simule um consumidor que cai/reinicia NO MEIO de uma sequência de
  mensagens publicadas via Streams+consumer group, e prove que ele retoma exatamente de onde parou
  (nenhuma mensagem pulada, nenhuma reprocessada duas vezes de forma que corrompa o acumulado) —
  contraste explícito com o que aconteceria em Pub/Sub (mensagens publicadas enquanto o consumidor
  estava fora do ar somem).
