- **Dedupe por HASH DE CONTEÚDO (byte-estável verificado)** — **nunca por nome de arquivo, nunca
  por timestamp de download.** Dois arquivos com o MESMO conteúdo byte-a-byte (mesmo se baixados
  em momentos diferentes, com nomes diferentes, ou re-baixados do mesmo dump) são o MESMO item
  para fins de ETL — um deles é descartado como duplicata, nunca reprocessado.
- **"Byte-estável verificado"**: não é suficiente hashear e confiar — prove com um teste que
  baixa/lê o MESMO conteúdo duas vezes (ex: dois arquivos idênticos, ou o mesmo arquivo lido duas
  vezes) e confirma que o hash é IDÊNTICO nas duas leituras, e que arquivos com um único byte
  diferente produzem hash DIFERENTE (o falsificador: se o hash não muda quando o conteúdo muda,
  o dedupe está quebrado silenciosamente).
- **Contra-exemplo que tem que ser rejeitado explicitamente**: dois arquivos com o MESMO NOME mas
  conteúdo DIFERENTE (ex: um dump re-publicado/corrigido pela Binance) NÃO são duplicata — o
  dedupe por nome de arquivo esconderia essa correção; só o hash de conteúdo pega isso certo.
